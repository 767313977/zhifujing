## 2. 算法一致性验证（只读重算）

对 2026-09-30 用 `stock_daily.close` 重算 20 日收益（20 个交易日前收盘 → 当日收盘）：

| 指标 | 结果 |
| --- | --- |
| 共同代码数 | 5,207 |
| 重算宇宙 / 存储宇宙 | 5,219 / 5,211 |
| Pearson 相关 | **0.9951** |
| 单位 | 存储为**百分数**（如 `5.2` 表示 5.2%） |
| 中位绝对差 | **0.00275 个百分点** |

结论：

1. `ret20` 与「过去 20 个交易日收盘收益率」高度一致，说明是**纯滚动计算**；
2. 在股票池不变的前提下，**追加未来数据不会改变历史日结果**；
3. 残余差异（12 个重算独有、4 个存储独有、0.0028pp 中位差）来自：股票池定义、复权处理、停牌日计数方式；
4. 该验证只覆盖 `ret20`，`ret120/250` 未逐一重算，标记 `PARTIAL`。

## 3. 版本判定规则（建议固化为代码闸门）

某交易日满足任一条即标记 `SUSPECT`，下游**拒绝读取**：

| 条件 | 说明 |
| --- | --- |
| `trade_date > stock_daily.max(trade_date)` | 孤儿日期 |
| 该日 `ret20` 空值比例 = 100% 且 `ret120` 非空 | 混版本 / 半成品 |
| 该日行数与前一交易日差异 > 20% | 股票池突变 |
| 缺少 `version_id` | 无法追溯算法版本（当前全部满足） |

## 4. 版本化设计（需授权后落地）

### 4.1 `rps_meta`

| 列 | 说明 |
| --- | --- |
| `version_id` | 主键，如 `rps_v2_20261115` |
| `algo` | 算法标识（收益率窗口、排名方式） |
| `windows` | `20,50,60,120,250` |
| `universe_rule` | 股票池定义（是否剔除 ST、次新、停牌） |
| `rank_method` | 横截面排名方式（如 mid-rank 百分位） |
| `input_start` / `input_cutoff` | 输入数据起止 |
| `code_sha` | 计算脚本 Git blob |
| `created_at` | 生成时间 |
| `status` | `ACTIVE` / `RETIRED` / `SUSPECT` |

### 4.2 `rps_daily` 扩展

新增 `version_id`，主键改为 `(trade_date, code, version_id)`；禁止跨版本拼接。

### 4.3 下游契约

```python
# 伪代码：读取必须指定版本
rows = load_rps(asof, version_id="rps_v2_20261115")
# 若该日 status=SUSPECT → 返回 UNKNOWN，不返回数值
```

## 5. 使用纪律

1. RPS **不得默认作为正向因子**。M6.1 归因显示：Model A 的 `rps20` Rank IC 为 **-0.166**，方向与预期相反；
2. 使用 RPS 必须同时报告：版本、股票池、当日有效样本、缺失比例；
3. 混版本日期（当前 2026-10-21）在所有回测中必须剔除；
4. 重新计算 RPS 时，必须重跑 `ret20` 重算验证，相关性 <0.99 视为算法变更，需要新版本号。
