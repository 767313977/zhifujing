## 1. 版本定义

| 字段 | 值 |
| --- | --- |
| `version_id` | `rps_v2_m63_20261115` |
| 算法 | 滚动交易窗口收益 + 横截面平均秩百分位 |

| 质量 | `PARTIAL` |

| 写入位置 | 仅 sandbox，**未写 `rps_daily`** |

## 2. 算法核验（5 个交易日 × 5 个窗口）

### 2.1 百分位映射

只用 legacy 的 `ret*` 重排名，再与 legacy `rps*` 对比：

| 指标 | 结果 |
| --- | --- |
| `mapping_corr_on_legacy_ret` | **25/25 组 = 1.0000** |

说明：本地百分位公式与旧库排名方式**完全一致**，差异不来自排名映射。

### 2.2 收益率一致性（从 raw close 重算 vs legacy）

| 窗口 | 相关系数最小值 | 相关系数中位数 | 中位绝对差（pp） |
| --- | ---: | ---: | ---: |
| 20 | 0.9711 | 0.9969 | 0.0034 |
| 50 | 0.9742 | 0.9972 | 0.0035 |
| 60 | 0.9772 | 0.9966 | 0.0036 |
| 120 | 0.9681 | 0.9835 | 0.2085 |
| 250 | 0.9799 | 0.9828 | 0.9174 |

- 20/50/60 日几乎完全一致（中位差 0.003pp），说明短窗口算法正确；
- 120/250 日差异随窗口变长而增大（0.21pp / 0.92pp），与**未复权**在多次分红/送转上的累积误差一致；
- 因此 `ret*` 的差异不是实现错误，而是价格域缺陷的直接证据。

### 2.3 未来数据独立性

对 2026-09-30：

| 项 | 结果 |
| --- | --- |
| 用全量矩阵 vs 截断到当日的矩阵计算 ret20 | 最大绝对差 **0.0**，完全相同 |
| 代码数 | 5,219 |

证明：追加未来行情不会改变历史日结果（在股票池不变的前提下）。

---

## 5. 使用规则

1. 读取必须指定 `version_id`；未指定 → 拒绝；
2. `quality_status=PARTIAL` 的版本只能用于**工程验证**，不得作为选股因子有效性的证据；
3. 修复复权数据后必须新建 `rps_v3_*`，不得覆盖 v2；
4. 旧数据继续 `LEGACY_UNKNOWN`，不得与 v2 混合计算排名或 IC。
