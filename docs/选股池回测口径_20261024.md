## 0. 数据来源与单位

| 表 | 用途 | 关键列 | 单位 |
|---|---|---|---|
| `stock_daily` | RPS 的日收益序列 | `trade_date, code, close, pct_chg` | 价格为**不复权**收盘；`pct_chg` 是真实涨跌幅（%） |
| `trade_calendar` | 交易日骨架（窗口按交易日数） | `trade_date` | — |
| `rps_daily` | RPS 落库结果（本功能新增） | `trade_date, code, ret120, ret250, rps120, rps250` | 涨幅 %；分位 0–100 |

| `stock_basic` | 名称（判 ST、展示） | `code, name` | — |

> 所以 RPS 的分母是「当日库内有日线的票」，回测时不要换成另一个分母，否则分位对不上。

## 1. RPS 相对强度榜

### 1.1 定义

对每只票、每个窗口 N ∈ {50, 120, 250}（50 日是 2026-10-24 加的，选股池「双高」档要用）：


```
ret_N = (∏(1 + pct_chg_i / 100) − 1) × 100        i 取窗口内最后 N 个有效日收益
RPS_N = 该 ret_N 在当日全市场（有 ret_N 的票）里的中位秩百分位
```

- **复利，不是价格比值**：库里是不复权价，直接 `close_T / close_{T-N}` 会被除权除息和送转带偏。
- **窗口按交易日**：两个窗口**各有自己的起点** —— `start_N` = `trade_calendar` 中不晚于 T 的第 N 个最近交易日；
  只复利 `trade_date >= start_N` 的行。**不能**写成「取最近 N 行」：停牌 / 漏采会让 N 行跨过更多交易日，
  算出来是更长的区间（2026-10-24 修，见 §6）。
- **停牌处理**：窗口内缺几天时，用**实际可用**的日收益复利；但窗口内可用天数必须 ≥ 窗口的 90%
  （120 → 至少 108 个；250 → 至少 225 个），否则该档记 `None`、不参与该档排名。
- **当天必须有这一行**：最后一根 K 线早于 T 的票（停牌）不进当天横截面。
- **当天覆盖率闸**：T 日有 `pct_chg` 的行数达不到股票池 90% 时**整批不写库**（与
  `scan_patterns._require_bars` 同一判据），避免一半票用当天、一半前一天。
- **中位秩**：并列值取中位，避免「一整片 0%」被读成极端。

```
rank = (count(< v) + count(== v) / 2) / N × 100
```

- 结果保留：`ret` 两位小数、`RPS` 一位小数。

### 1.2 参照实现（与线上逐字一致）

```python
MIN_COVERAGE = 0.9
WINDOWS = (50, 120, 250)

def window_values(rows: list[tuple[date, float]], start: date) -> list[float]:
    """只留不早于窗口起点的行 —— 窗口按交易日，不按「最近 N 行」。"""
    return [pct for day, pct in rows if day >= start]

def ret(values: list[float], days: int) -> float | None:
    if len(values) < int(days * MIN_COVERAGE):   # 120→108, 250→225
        return None
    factor = 1.0
    for pct in values[-days:]:
        factor *= 1 + pct / 100
    return round((factor - 1) * 100, 2)

def mid_rank(ordered: list[float], value: float) -> float:
    left = bisect_left(ordered, value)
    right = bisect_right(ordered, value)
    return round((left + right) / 2 / len(ordered) * 100, 1)
```

流程：

1. `target = max(stock_daily.trade_date where pct_chg is not null)`；
2. **覆盖率闸**：`target` 当天 `pct_chg` 非空的行数 / `stock_universe` 行数 ≥ 90%，否则不写库；
3. 取 `trade_calendar` 中 `<= target` 的最近 250 个交易日（降序），
   `start_N = 第 N 个`（120 → `days[119]`，250 → `days[249]`）；
4. 读 `stock_daily` 中 `trade_date between min(start_N) and target and pct_chg is not null` 的
   `(code, trade_date, pct_chg)`，按 `code, trade_date` 升序**流式**处理；
5. 按 code 分组：**先丢掉最后一根早于 `target` 的票**，再按 `start_N` 过滤后算 `ret_N`；
6. 分别对两档有值的票排序、算 `rps120 / rps250`；
7. 写入 `rps_daily`（每天每人一行，`ON CONFLICT (trade_date, code) DO UPDATE`）。

### 1.3 榜单档位（2026-10-24 改）

| `mode` | 条件 | 排序 |
|---|---|---|
| `all`（**默认**） | 两档（120/250）都有值且 ≥ `min_rps` | `rps250` 降序 |
| `dual` | `rps50 ≥ 90` 且 `rps120 ≥ 85` | `rps50 + rps120` 降序 |
| `line_red` | 三档里任一 ≥ 90（陶博士「一线红」） | 三档最大值降序 |

> ⚠️ **默认不是 `dual`**：口径对齐后重跑（§6，2026-10-24），「双高 × 突破」只在最近
> 255 个交易日有效（10 日超额 +3.1~4.1%），**5 年长历史全部为负**（−0.6~−1.6pp 的超额差）。
> 方向不一致 → `dual` 只作参考视图，不当默认。

每行还带：

- `hits`：当天命中 `BREAKOUT_KEYS = (new_high, three_white_soldiers, ma_golden_cross,
  turtle_breakout, volume_surge)` 的中文形态名；
- `tags`：`一线红`（任一档 ≥ 90）/ `三线红`（三档都 ≥ 90）/ `掉队`（`rps250 ≥ 90` 且 `rps120 < 80`）；
- `off_high_pct`：收盘距近 250 个交易日**最高收盘**的百分比（用 `pct_chg` 复利成净值曲线算，≤ 0）；
- `industry`：`stock_basic.industry` 按 `-` 拆的**末段**；`industry_top` 则按**一级行业**统计前 5。

`breakout_only` / `trend_template` 两个开关在**排序之后**按序评估最多 300 只
（`_FILTER_SCAN_CAP`）—— 榜单本身是「最强的一批」，300 名之后还满足条件的票不该按强度混进来。

### 1.4 取数 SQL（回测时可直接用）


```sql
-- 1) 窗口内的日收益（按 code, trade_date 升序）
WITH days AS (
  SELECT trade_date FROM trade_calendar
  WHERE trade_date <= :target
  ORDER BY trade_date DESC
  LIMIT 250
)
SELECT code, trade_date, pct_chg
FROM stock_daily
WHERE trade_date >= (SELECT MIN(trade_date) FROM days)
  AND trade_date <= :target
  AND pct_chg IS NOT NULL
ORDER BY code, trade_date;
```

```sql
-- 2) 当日全市场分位所需的值（先按上面的 Python 算出 ret，再排名）
SELECT code, ret250 FROM rps_daily WHERE trade_date = :target AND ret250 IS NOT NULL;
```

### 1.5 容易踩的坑

- **不能拿 `rps_daily` 当历史样本**：线上只存「跑过的那一天」。回测必须用 `stock_daily` 按上述口径**逐日重算**，
  否则就是拿未来数据。
- **不要用 `close` 比值**替代 `pct_chg` 复利（除权除息日会给出假的 −30%）。
- **不要剔除 ST / 北交所**：RPS 目前**不剔除**，剔除会改变分母，分位就变了。
  如果回测想只做主板+创业板，那是在 RPS 之上再过滤，不要重算分位。
- 新股：上市不足 108 / 225 个交易日的票，对应档为 `None`，不参与该档排名。

## 2. 首板一进二候选

### 2.1 筛选漏斗（默认参数）

| 步骤 | 条件 | 单位/说明 |
|---|---|---|
| 1 | `pool_type = 'up'` | 只看涨停池 |
| 2 | `consecutive = 1` | **首板**（当日第一次涨停） |
| 3 | `open_times = 0` | **没炸过板** |
| 4 | `first_seal_time is not null and first_seal_time <= :before` | 默认 `140000`（14:00 前），排掉尾盘偷袭 |
| 5 | `float_mv between :min_float_mv*1e8 and :max_float_mv*1e8` | 默认 20~300 **亿** |
| 6 | `amount >= :min_amount*1e8` | 默认 3 **亿** |
| 7 | 名称含 `ST`（`"ST" in name.upper()`）→ 剔除 | 含 `*ST` |
| 8 | 代码以 `4 / 8 / 92` 开头 → 剔除 | 北交所 |
| 9 | 当日同题材涨停家数 `theme_count >= :min_themes` | 默认 3；`0` = 关闭该条件 |
| 10 | `seal_amount / float_mv × 100 >= :min_seal_ratio` | 默认 0 = 关闭；页面上可切 ≥0.3% / ≥1% |

两个封单口径（都返回，别混）：

```
seal_ratio      = seal_amount / float_mv × 100      # 封单额占流通市值（%）
seal_to_amount  = seal_amount / amount × 100        # 封单额占当日成交额（%）
```


排序（2026-10-24 改）：不再是「题材家数优先」，改成三个**当日候选内分位**的加权：

```
score = pct(theme_count) × 0.4 + pct(seal_ratio) × 0.4 + pct(首封早晚) × 0.2
```

- 分位口径：`rank / (n − 1) × 100`，n = 当日通过全部条件的候选数（**不含** limit 截断）；
- 首封越早越好，所以对 `−HHMMSS` 算分位；
- 封单比缺值按 0 参与（等于排在最后）；
- 权重是起手值（`SCORE_W_*`），本地 20 天样本（82 只）两种排序的次日表现没有显著差异，
  **别把权重当成结论** —— 用页面上的次日验证面板对比之后再说。


> ⚠️ `consecutive = 1` **不等于真首板**：前几天涨停过、断一天再涨停的票，当日连板数同样是 1。
> 2026-10-24 起返回 `recent_limit_ups`（D 之前 10 个交易日 `pool_type='up'` 的次数），
> 并可用 `only_true_first_board=true` 只留 0 次的那批。计数按 `trade_calendar` 取前 10 个交易日。

另外两个展示字段（只描述当天，不参与筛选）：

- `board_shape`：当日 `open = high = low = close` → `一字`；`open = high` 且 `low < open` → `T字`；其余为空。
- `theme_rank`：在该题材**当日全部涨停股**里按 `first_seal_time` 的排名（1 = 最早封板），
  分母就是 `theme_count`。注意参与排名的是全部涨停股，不只是候选。
- `theme2` / `theme2_count`：同一只票挂的第二热题材。

> 第 3 条的 `open_times == 0` 2026-10-24 核查过：库里涨停池 18003 行（255 个交易日，
> 2025-09-08 ~ 2026-09-24）**没有空值**，所以不会把「未知」误当成「炸过板」。
> 换数据源/回补口径时要重跑：
>
> ```sql
> SELECT trade_date, COUNT(*) FROM limit_pool
> WHERE pool_type='up' AND open_times IS NULL GROUP BY trade_date ORDER BY trade_date;
> ```


其中：

```
seal_ratio = seal_amount / float_mv × 100      # 封单额占流通市值的百分比，保留 2 位
```

### 2.2 题材家数的口径（**最容易对不上的地方**）

- 来源是 `stock_concept`，即开盘红**精选板块**，**只覆盖涨停股**，且一只票可能挂多个板块；
- 家数 = 当日同 `concept` 的**涨停股只数**（`COUNT(DISTINCT code)`）；
- 单只票取「它所属板块中家数最多」的那个作为 `theme`，其家数为 `theme_count`；
- 计数发生在剔除 ST / 北交所**之前** —— 也就是说 `theme_count` 里可能包含 ST 或北交所票。
  回测复算必须保持这个顺序，否则数字会差 1~2 家；
- 没有精选板块的票 `theme = null, theme_count = 0`，默认参数下会被第 9 条筛掉。

### 2.3 取数 SQL

```sql
-- 1) 候选（第 1~8 条里与 SQL 有关的部分；ST / 北交所建议在 Python 里判）
SELECT l.code,
       COALESCE(b.name, l.name) AS name,
       l.consecutive, l.open_times,
       l.first_seal_time, l.last_seal_time,
       l.float_mv, l.amount, l.seal_amount, l.turnover, l.industry
FROM limit_pool l
LEFT JOIN stock_basic b ON b.code = l.code
WHERE l.trade_date = :day
  AND l.pool_type = 'up'
  AND l.consecutive = 1
  AND l.open_times = 0
  AND l.first_seal_time IS NOT NULL
  AND l.first_seal_time <= :before            -- '140000'
  AND l.float_mv BETWEEN :min_mv AND :max_mv  -- 单位：元
  AND l.amount >= :min_amount                 -- 单位：元
ORDER BY l.first_seal_time;
```

```sql
-- 2) 题材家数
SELECT concept, COUNT(DISTINCT code) AS cnt
FROM stock_concept
WHERE trade_date = :day
GROUP BY concept;

-- 3) 每只票挂了哪些板块
SELECT code, concept FROM stock_concept WHERE trade_date = :day;
```

## 3. 回测口径（照这个做才能和线上对上）

### 3.1 时间与成交假设

- **信号**：T 日收盘后生成（所有输入都是 T 日收盘可得的数据：日线、涨停池、精选板块）。
- **买入**：T+1 **开盘价**。以下两种情况视为**无法成交**，应当剔除并单独统计比例：
  - T+1 开盘即一字涨停（`open == high == 涨停价`）；
  - T+1 开盘价 ≥ 涨停价（集合竞价就封死）。
- **卖出**：至少给三档 —— T+1 收盘、T+3 收盘、T+5 收盘。打板类策略的收益分布极度右偏，
  **只看均值没有意义**，要一起看中位数、胜率、最大回撤、以及「次日跌停无法卖出」的比例。
- **复权**：持有期收益用 `pct_chg` 复利，不要用不复权收盘价比值。
- **费用**：至少扣佣金（双边约万 2.5）+ 印花税（卖出千 1）+ 滑点（建议按 0.1~0.3% 计）。

### 3.2 防未来函数清单

- RPS 必须用 ≤T 的日线逐日重算（见 1.4 第一条）。
- 首板池的 `theme_count` 用的是 T 日当天数据，属于收盘后可知，**不算未来函数**；
  但不要把 T+1 的涨停家数混进来。
- `limit_pool` 的 `consecutive` 是**当日**连板数，不是「次日能否连板」。
- 停牌股、退市股的处理要在样本里显式声明（退市股按最后交易日收盘价结算，不能直接丢弃，
  否则是幸存者偏差）。

### 3.3 建议的验证流程

1. 从 `stock_daily` 按 1.2 的口径复算某几天的 RPS，与 `rps_daily` 对照（允许 ±0.1 的分位误差、
   ret 完全一致）；
2. 用 2.3 的 SQL 复算某几天的首板池，与页面结果逐只对照（重点看 `theme_count`）；
3. 用**同一套代码**跑 2019–2021 / 2022–2026 两段，做样本外；
4. 参数只做小网格（首封时间 3 档 × 市值 2 档 × 题材 2 档 = 12 组），每组都看 T+1/T+3/T+5
   的中位数与胜率，别挑累计收益最高的那一组；
5. 任何改动先落到 `services/pools.py`，页面与回测共用同一份实现 —— 口径分叉过的教训见
   `services/patterns.is_st` 的注释。

### 3.4 页面上的「次日验证」面板（2026-10-24）

页面两块表上方各有一行汇总，数据来自 `GET /api/pools/first-board/track` 与
`/api/pools/rps/track`。它**不是**另一套口径，而是把 §3.1 的成交假设**写进代码**：

| 指标 | 算法 |
|---|---|
| 样本 | 近 N 天按当前条件选出的候选里，**有次日日线、且买得到**的只数 |
| 晋级率 | 次日仍在 `limit_pool(pool_type='up')` 的只数 ÷ 有次日日线的候选数 |
| 开盘溢价 | `open_{T+1} / prev_close − 1`，`prev_close = close_{T+1} / (1 + pct_chg_{T+1}/100)`（除权日的交易所参考价） |
| 收盘收益 | 直接取 `pct_chg_{T+1}` |
| 大面率 | 收盘 ≤ −5% 的只数 ÷ 买得到的样本数 |
| 跌停率 | 次日在 `limit_pool(pool_type='down')` 的只数 ÷ 买得到的样本数 |
| 一字买不进 | 次日晋级且**开 = 高 = 低 = 收**的只数 ÷ 有次日日线的候选数；**不进收益均值** |
| 待验证 | 次日日线还没采到的那一天，整日不计入统计 |

RPS 面板那一行复用了 `pattern_track._curves`（形态跟踪同一份行情矩阵、同一套
「当日全市场等权」基准），所以超额口径与形态页一致；`rps_daily` 只存跑过的日子，
`days` 就是真实参与统计的天数，**不足 5 天时页面会写「样本不足 5 天」**。

**首板面板的 `order` / `top`（2026-10-24 加）**：`top=0`（接口默认）统计**全部**
候选 —— 全量时顺序不影响任何数字，所以只加 `order` 是没用的；页面把 `top`
固定成列表的 50 只，这样「排序」切到「量价因子分」时，下面这行汇总就是
「按因子分挑出来的前 50 只，历史上次日怎么样」，与表格里看到的顺序一致。
对照实验见 `docs/回测_量价因子IC_20261024.md` §7。

> ⚠️ 这两行只能证明「这套阈值在过去 20 天怎么样」，样本量通常只有几十到一两百只，
> 别拿一两天的差异定参数；也别忘了 §3.1 里的费用还没扣。

## 4. 已知局限

- 首板池是**盘后候选**，无法判断次日承接；本站没有盘中数据。
- 精选板块只覆盖涨停股，非涨停股的题材归属不可用（`stock_concept` 的固有限制）。
- `limit_pool` 只保留最近 15 个交易日的原始接口数据；更早的历史来自每日落库，
  如果某天采集缺失，那天的首板池是空的，**不要把它当成「当天没有首板」**。
- RPS 的分母随库内日线覆盖变化（新股上市、池子调整都会影响），跨年比较分位时要注意这一点。
- `ret250` 用 250 个**交易日**，不是 12 个自然月，跨市场对比时先换算口径。
