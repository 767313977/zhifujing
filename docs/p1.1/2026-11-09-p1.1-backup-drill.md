## 1. 六道门禁（在受控隔离环境、对生产一致性备份执行）

所有命令中的 `<COPY>` 指生产备份副本路径，`<REL>` 指发布等价副本。

### 门禁 1：原始基线

```bash
sqlite3 "<COPY>" "PRAGMA quick_check;"                       # 期望 ok
python scripts/prod_readonly_audit.py --db "<COPY>" --json baseline_audit.json
python scripts/schema_inventory.py --db "<COPY>" --json baseline_schema.json
```

保存：文件大小、`quick_check`、四张主表行数与首末日期、关键用户表行数
（`app_user / watchlist / trade_plan / trade_journal`）、Schema 清单、`db_uuid`（若已有）。

判据：`quick_check=ok`；用户表行数、生产独有数据**必须**在演练前后一致。

### 门禁 2：Schema 迁移

```bash
python scripts/migrate_db.py --db "<COPY>" --status          # 先看差集，应只读
python scripts/migrate_db.py --db "<COPY>" --apply --backup "<COPY_BEFORE>"
python scripts/migrate_db.py --db "<COPY>" --status          # 期望 兼容=True
python scripts/schema_inventory.py --db "<REL>" --compare "<COPY>" --diff-json diff.json
```

判据：迁移后的差集只剩「非模型表」（manifest / 修订表）；重复 `--apply` 返回 0 列 / 0 索引；
迁移失败可用 `<COPY_BEFORE>` 恢复。

> 本机等价副本实测：补 23 列 + 1 索引，第二次 0/0；A→B 差集 +6 表 / +23 列 / +7 索引 / +24 触发器。
> **这些数字不是生产目标**，生产以 `--status` 的实际差集为准。

### 门禁 3：历史增量导入（按生产主键重新统计）

```bash
# 只统计，不写库
python scripts/import_rps_history.py --source "<研究库>" --target "<COPY>"
# 核对 missing_keys / fill_* / conflicts 后执行
python scripts/import_rps_history.py --source "<研究库>" --target "<COPY>" \
    --apply --backup "<COPY_BEFORE_IMPORT>" --report import.json
```

成分股与 manifest 按同一原则：**只插入生产缺失的 (date, sector/code)**，已存在行不覆盖；
冲突必须单独列出后人工裁决。

判据：
- 新增主键数 = 研究库候选 − 生产已有（不得沿用本机的 1,262,706 / 1,272,912）；
- 冲突 = 0 或逐条有裁决记录；
- 生产独有记录数不变；
- 用户表行数不变。

### 门禁 4：修订水位

```bash
python scripts/install_data_revision.py --db "<COPY>"
python scripts/install_data_revision.py --db "<COPY>" --status
```

判据：8 个域、24 个触发器、`db_uuid` 存在、`cache.state=ready`；写一行后版本 +1；
事务回滚版本不变；重启后不复用旧缓存。

### 门禁 5：候选应用验收

```bash
DB_PATH="<COPY>" SCHEDULER_ENABLED=false CATCHUP_ON_START=false \
  .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8100
```

执行：10 个旧业务接口、6 个研究接口（含 `allow_fallback=false` 与孤儿日期）、
鉴权（未登录 401/跳转、普通用户看不到 `data_health`）、真实浏览器 E2E、
缓存冷/热请求、并发限流（503 + `Retry-After`）、模拟盘后采集写入。

判据：接口全 200；数据状态与 §A 的矩阵一致；用户数据导入前后一致；无 5xx；无 `database is locked`。

### 门禁 6：故障回滚

步骤与判据：

1. 停候选应用；
2. 用 `<COPY_BEFORE_SCHEMA>` 覆盖副本；
3. `quick_check=ok`；四张主表行数回到基线；用户表与生产独有数据不丢；
4. 用**候选版本**启动 → 必须失败并提示迁移（不会偷偷改库）；
5. 用旧版本 + 旧库启动 → 若旧版本 < `915a75a`，其 `init_db()` 会自动迁移，故回退必须
   连库一起回退；
6. 缓存身份/修订版本不复用：`data_revision` 表随备份一起回退。

记录：每一步实际耗时、峰值内存、失败点。

## 3. 生产停写与切换顺序（P1.1-06 设计，不执行）

### 3.1 时间窗必须避开的任务

| 时刻 | 任务 | 冲突 |
| --- | --- | --- |
| 15:05 | 盘后主链采集 | 写库高峰 |
| 17:30 / 19:30 / 22:35 | 尾部链（龙虎榜、两融、ETF、期指） | 写库 |
| 22:00 / 22:30 | 板块成分股预取与重试 | 大量写库 |
| 次日 08:30 | 昨日成分股补采 | 写库 |
| 23:10 | 数据库备份 | 读全库 |

建议窗口：**非交易日 10:00–12:00**（或交易日 23:40 之后），并确认当天 08:30 补采已结束。

### 3.2 切换步骤

1. 取得书面生产发布授权（本阶段不申请执行，只设计）。
2. 校验 RC：`git rev-parse HEAD` 等于 `docs/p1.1/rc-manifest.json` 的 `git.head`，
   `frontend/dist` 摘要等于 `frontend_dist.digest`，测试结果与清单一致。
3. 停服务与调度：`systemctl stop fupan`（调度器随之停止）。
4. 一致性备份 + 独立副本：
   `sqlite3 "file:...?mode=ro" ".backup '/backup/fupan-$(date +%F-%H%M).db'"`，
   `quick_check` 通过后复制一份到异地/受控目录。
5. 显式迁移：`python scripts/migrate_db.py --db <生产库> --apply --allow-main-db`。
6. 增量导入：`import_rps_history.py`（主键差集按生产统计）+ 成分股/manifest 导入。
7. 安装修订触发器并 `--status` 验证 ready。
8. 启动前 **verify 冒烟**：`FUPAN_SCHEMA_MODE=verify python -c "..."` 或直接启动；
   日志必须出现「未执行任何 DDL」。
9. 启动应用：首次启动设 `CATCHUP_ON_START=false`，避免「已过 15:05 就补采」在迁移刚完成时
   触发写库；确认页面与只读接口正常后，再设回 `true` 并 `systemctl restart fupan`。
10. 只读冒烟：健康检查、旧接口、研究接口、登录；观察 `database is locked`、5xx、RSS。
11. 恢复调度：确认 APScheduler 只注册一份（单 Worker）、当天任务未被重复执行。
12. 任一门禁失败：停应用 → 恢复备份 → 旧版本启动（如旧版本会 `init_db()`，必须同时回退库）。

### 3.3 迁移持续时间与备份的相互影响

- 迁移本身是秒级；**耗时主要在历史导入**（等价副本 2 分钟量级，生产可能更长）。
- 导入期间禁止调度写入：`systemctl stop` 后调度器不会重启，除非有人手工启动。
- 若窗口跨越 23:10，备份任务会在停服时跳过；必须在切换完成后手工补一次备份。
- 若导入超过窗口，按「门禁 6」回滚，不要在半完成状态下恢复调度。
