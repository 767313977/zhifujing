## 2. 交付的采集包（运维可直接执行）

| 文件 | 用途 | 安全性 |
| --- | --- | --- |
| `deploy/prod_probe.sh` | 服务器侧：内存/CPU/cgroup/进程/磁盘/nginx 超时/OOM/采集期 RSS 峰值 | 只读，不访问数据库 |
| `scripts/prod_readonly_audit.py` | 数据库侧：表统计、逐日覆盖、RPS 新字段与孤儿日、manifest、collect_log、格式 | `mode=ro`，只执行 SELECT/PRAGMA |
| `scripts/schema_inventory.py` | Schema 侧：表/列/索引/触发器/视图清单与双向差集 | `mode=ro`，不做 DDL |
| `scripts/release_manifest.py` | 发布候选清单（SHA/tree/依赖/Schema 指纹/构建摘要） | 只读 |

### 2.1 执行顺序（全部在服务器本机）

```bash
# ① 系统资源（输出后按 §4 脱敏）
sudo bash deploy/prod_probe.sh > prod_probe.txt 2>&1

# ② 用官方备份 API 建一致性副本（不要直接复制 .db 主文件）
python - <<'PY'
import sqlite3
src = sqlite3.connect("file:/srv/fupan/backend/data/fupan.db?mode=ro", uri=True)
dst = sqlite3.connect("/srv/fupan/audit/prod_copy.db")
src.backup(dst); dst.close(); src.close()
PY

# ③ 在副本上做数据与 Schema 审计
python scripts/prod_readonly_audit.py --db /srv/fupan/audit/prod_copy.db \
    --start 2026-07-03 --end 2026-11-09 --json prod_audit.json
python scripts/schema_inventory.py --db /srv/fupan/audit/prod_copy.db \
    --json prod_schema.json
```

`prod_copy.db` 只留在服务器受控目录；回传只回 `prod_probe.txt`、`prod_audit.json`、
`prod_schema.json` 三个文本文件。

## 3. 需要回传的字段（逐项对应门禁）

### 3.1 服务器资源（`prod_probe.txt`）

| 项 | 用途 | 判定 |
| --- | --- | --- |
| `free -m` | 物理内存 / 可用 / Swap | 可用 ≥ 峰值 × 1.5 |
| `nproc` | CPU 核数 | 观察采集与扫描是否争抢 |
| `MemoryCurrent / MemoryMax / TasksCurrent` | cgroup 上限与当前占用 | 峰值 < 上限的 2/3 |
| `ExecStart` | 实际 Worker 数 | **必须单 Worker**；多 Worker 需重做限流/缓存验收 |
| `ps --sort=-rss` | 同机其他负载 | 计入总预算 |
| `df -h` | SQLite 所在盘 | 可用 ≥ 生产库 × 3 |
| nginx `proxy_read_timeout` | 慢接口容忍度 | ≥ 最慢接口 × 2（等价副本 low-start 8.5 s） |
| 采集期 RSS 峰值 | 真实内存预算 | 不得用开发机 375 MB 代替 |
