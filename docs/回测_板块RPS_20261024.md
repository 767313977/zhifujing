# 板块 RPS：口径、榜单与延续性回测

> 日期：2026-10-24
> 代码：`backend/app/services/sector_rps.py`、`GET /api/pools/sector-rps`、`/api/pools/sector-rps/track`
> 页面：`/pools` 第三块「板块 RPS（20 日强度分位）」
> 数据：`sector_daily`（开盘红板块指数，2025-09-08 ~ 2026-09-24，精选 279 个 / 行业 104 个）

## 1. 为什么不用 `sector_member` 算

`sector_member` 只有**当天**的成分快照（打开板块时现取），拿它回看历史就是前视偏差：
今天被划进「机器人概念」的票，去年并不在那个板块里；按今天的成分回算去年，等于
提前知道谁会进热点。

`sector_daily.pct_chg` 是开盘红**每天自己算的板块涨跌幅**（成分当日生效），本身带历史，
不存在这个问题。所以板块强度只用它，**不自己拼成分**。

代价：拿不到「板块内个股」的逐日归属，因此**不能用板块 RPS 直接做个股筛选**
（`theme_rank` 那套只在当天可用）。能做的是两件不会骗人的事：

1. 展示今天哪些板块最强；
2. 在**板块指数**层面验证动量有没有延续性。

## 2. 口径

与个股 RPS 完全一致（`services/rps.py`）：`pct_chg` 复利、窗口按交易日截、中位秩百分位。

```
ret_N(板块) = ∏(1 + pct_chg_i / 100) − 1        i 取窗口内最后 N 个交易日
RPS_N(板块) = 该 ret_N 在**当天所有板块**里的中位秩百分位
```

- 窗口：5 日 / 20 日；
- 两个口径（精选板块 / 行业）**各自排名，不能混比**；
- 当天没有那一行的板块（漏采 / 已下线）退到窗口内最近一次的展示信息，避免榜单出现空名字。

## 4. 延续性回测（买「最强的板块」比买全部板块更好吗）

规则：每个交易日按 RPS20 取最强 `top` 个板块，从**次日**起持有 5 / 20 个交易日
（板块指数 `pct_chg` 复利）；基准 = 当日全部板块等权。超额逐样本减去当日基准。

| 口径 | 样本 | top | 5 日超额 | 20 日超额 |
|---|---|---:|---:|---:|
| 精选板块 | 近 200 个交易日 | 5 | **+0.22pp** | **+0.86pp** |
| 精选板块 | 近 200 个交易日 | 10 | +0.17pp | +0.50pp |
| 精选板块 | **近 60 个交易日** | 5 | **−1.46pp** | **−2.69pp** |
| 行业 | 近 200 个交易日 | 5 | **+0.43pp** | **+1.26pp** |
| 行业 | 近 200 个交易日 | 10 | +0.22pp | +1.00pp |
| 行业 | **近 60 个交易日** | 5 | **−1.54pp** | **−2.78pp** |

## 5. 结论

1. **200 天尺度上板块动量是正的**：行业口径 20 日超额 +1.26pp 比精选板块的 +0.86pp 更稳
   —— 精选板块轮动太快，行业慢一些、噪声更小。这与「个股 RPS 单独无效」不矛盾：
   板块指数是成分平均，动量在**聚合层面**更干净。
2. **最近 60 天是负的**（−1.5 ~ −2.8pp）：和 RPS 那次一样，最近三个月是动量反转的环境。
   所以**不能把它当成稳定 alpha**，页面那行「近 N 日」汇总就是让人自己看当前处在哪一段。
3. **不做个股筛选**：没有历史成分归属（见 §1），任何「按板块 RPS 选票」的回测都会有前视偏差。
   `theme_rank`（当天题材内首封排名）是另一回事，那个只用当天数据。
4. 页面上的定位：**板块温度计 + 观察指标**，不是买卖信号；收益口径也明确写着
   「板块指数，不是个股」。

## 6. 局限

- `sector_daily` 只有约一年历史（2025-09 起），无法做样本外分期；
- 板块指数按开盘红口径，与申万 / 同花顺行业不可直接对齐；
- 收益不含交易费用；板块指数买不到，落地到个股还要再过一层选股（正是我们缺的那层）；
- `member_count` / `leader_name` 依赖 22:00 那次成分预取，白天可能是空的。

# 服务层（本地库）

from app.db import session_scope
