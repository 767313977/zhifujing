# 回测：形态命中列表按量价因子分排序（2026-11-01）

> 脚本：`scripts/backtest_patterns.py --order-split factor`（本次新增）
> 数据：`backend/data/history.db`（1250 根 ≈ 1230 个交易日，2021-09-14 ~ 2026-10-19），零外部请求
> 口径：`--history --board prod`（主板 + 创业板 + 科创板，不含北交所；悟道六池 + 金叉大阳仍只收 20cm）
> 入场：默认 `close`（信号日收盘；两组完全相同，只换排序）

## 1. 这次测的是什么

形态页要加一个**可选**的排序开关：默认按形态评分，切到「因子分」时按
`rev20 / illiq20 / amp20` 的**池内分位**加权排序（`services/factor_score`，权重 0.30 / 0.30 / 0.40，
与首板池、RPS 榜同一套）。

这里只回答一件事：**同一个信号日、同一个形态的全部命中里，「评分前 N」与「因子分前 N」
之后的 10 日超额有没有差别**。

```
每个信号日、每个形态：
  评分组   = 当天命中按形态评分降序取前 N
  因子分组 = 当天命中按因子分降序取前 N（因子分在当天这批命中内部算分位）
  两组的入场方式、持有期、基准完全相同，只换选出的是哪几只
  指标     = 10 日超额 = 样本 10 日收益 − 同实际入场日的基准均值（与主表同一套基准）
```

N 取 5 / 10 / 20。命中数不超过 N 的日子两组取到的是同一批票，会把差异稀释掉，
所以另报一张「当天命中数 > N 的日子」。

## 5. 结论

1. **30 个格子的差值全部为正**（5 个形态 × 3 档 × 2 种口径），方向一致：在同一批
   当天的命中里，先看「跌得多、波动小、不流动」的那批，10 日超额比按形态评分挑要高
   0.08~0.75pp，胜率高 1~4pp。这与 IC 报告「反转 + 低波动在 A 股横截面占优」是同一条。
2. **N 越小、改善越大**（缩量回踩 N=5 差 +0.68~0.75，N=20 只剩 +0.16~0.28）：因子
   排序的价值集中在「最靠前那几只」，把名单放大到二三十只时两组的差别自然收窄。
3. **形态越「追强」，因子的帮助越明显**：放量突破前高、放量上涨、创 N 日新高在 N=5 时
   提升 0.56~0.67pp；均线多头排列只有 0.08~0.19pp —— 它本身就是趋势形态，与
   「反转 / 低波」因子最不搭。
4. **排序不能把负超额变成正超额**：除了缩量回踩（全样本 10 日超额 +0.06%、N=5 的因子组
   +0.58%），其余三个形态在 N=5 的因子组里**仍然是负的**（−0.03% ~ −0.40%）。这是
   「在一批本来就不太行的信号里挑相对不那么差的」，**不是**新的赚钱策略，
   也不能据此说「因子分高 = 更会涨」。
5. 因此这个开关的定位是：**默认关闭、只改顺序**；页面文案只说「池内分位，只对当天
   这一批命中有意义，不跨池比较」。

## 6. 局限

- **未扣费用**：佣金 / 印花税 / 滑点 / 冲击成本都没算；N=5 时因子组比评分组多出的
  0.08~0.67pp 里，换手成本会吃掉一部分（两组的换手次数相同，但选中的票不同）。
- **入场口径**：本次用 `close`（信号日收盘）。打板 / 突破类更真实的是次日开盘 +
  剔除一字板（`--entry next_open --skip-unbuyable`），两组同口径换掉不影响「谁更好」的
  方向，但绝对数字会变。
- **因子窗口的微小差异**：回测里因子分用「这只票自己的最近 20 根」，生产用
  `TradeCalendar` 的最近 20 个交易日。停牌票在回测里窗口会多跨几天，理论上会让极少
  数票的分位有偏差；这不影响排序方向。
- **池子口径一致**：生产 `/hits?order=factor` 是在「当天的全部命中」里算分位，
  页面上的板块 / 评分下限筛选发生在**算完分位之后**（前端只是隐藏行），与这里的
  「同一个信号日的全部命中」一致。
- **形态覆盖**：只跑了信号量最大的 5 个非悟道池形态（合计 25.3 万条）。悟道六池的判定
  在 5 年 × 全池下是逐日 Python 循环，单次全量要一小时以上，本次没跑；它们的信号量
  （1~2 万条/池）也小于这 5 个。
- **沿用主回测的数据限制**：幸存者偏差（股票池是当前在池的票）、总市值 2000 亿过滤
  未复现、ST 名称回补、20 日去重只是独立样本的近似 —— 见 `--order-split` 报告末尾的
  「数据限制」一节。

## 7. 复现

```bash
python scripts/backtest_patterns.py \
  --pattern volume_surge,ma_bull,new_high,volume_breakout,dry_pullback \
  --history --board prod --order-split factor --bars 1250 --samples 0
```

输出末尾的「排序对照」表就是上面两节；`--order-split` 必须配 `--history --board prod`
（脚本会直接拒绝其它组合）。
