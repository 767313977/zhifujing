# 选池策略（速查）

> 这份是**策略速查**：六个池子各自「是什么 / 有什么证据 / 该怎么用 / 已知局限」。
> 「为什么这么定、踩过哪些坑、试过哪些走不通的路」写在
> [设计文档](plans/2026-09-17-fupan-site-design.md) §8.83 ~ §8.89，这里不重复。
> 最后更新：2026-10-09。

## 0. 读这份文档前先记住三条

1. **所有数字都来自同一段行情** —— 主库每票 260 根 ≈ 近一年（4945 只，截至 2026-09-29）。
   它只说明「在这段行情里长这样」，**别外推**。要更强的结论得换更长窗口（`--history`）重跑。
2. **基准有两种，看池子好坏一律看「同板块基准」**：
   - **全市场等权** —— 「跑赢大盘多少」，里面混着**板块 beta**
   - **创业板+科创板等权** —— 「在自己的板块里跑赢多少」，把 beta 剔掉
   今天的实测证明这个区分很要紧：华宝早期用全市场基准是 +0.43%（5 日）、
   换同板块基准就变成 **−0.16%** —— 它的「正超额」其实只是那段行情里这两块强。
3. **回测口径固定**（与 `scripts/backtest_patterns.py` 一致）：只用判定日及之前的数据、
   同一只票 20 个交易日去重、基准 = 同一天等权。**生产落库不去重**（一天一只票可能连着命中），
   所以「回测命中数」不等于「页面上每天几只」。

## 1. 六个池子的共同口径

| 项 | 口径 |
| --- | --- |
| 板块 | **创业板（300/301/302）+ 科创板（688/689）** —— 2026-10-09 起，**六个池子都卡**；不含主板、不含北交所 |
| 为什么不含主板 | 本套阈值按 **20cm** 校准（「太热」= 收盘 ≥12% / 冲高 ≥18%；「封板排除」= 收盘 ≥9.5% + 收在最高 + 几乎无上影），主板 10cm 上这些条件天生打不到 |
| 候选池 | **只有「明天盯 / 明天预案」用**：当日冲高幅度 ∈ [4.5%, 22%]、收盘涨幅 ∈ [−3%, 20.5%]，按冲高降序、不设条数上限、零请求（读本地日线）。其余四个池子**不限候选池**（它们的票今天往往很安静，用「今天强势」当候选等于全筛掉） |
| 量比 | 当日成交量 ÷ **近 20 日均量（不含当日）** |
| 到线率 / 破位率 | 都用**收盘**判；窗口 5 个交易日；破位用池子自己的作废位，没有的用**命中日最低价**当代理（标「代理」） |
| 复现 | `python scripts/backtest_patterns.py --pattern <key> --board wudao`（`--board wudao` 就是上面那个板块口径） |

## 2. 六个池子

数字格式统一为 **5 / 10 / 20 / 60 日超额（%）**，括号里是命中条数。
每行给「同板块基准」与「全市场基准」两套，**结论看前者**。

### 2.1 明天盯 `wudao_sample` —— 核心观察池

- **是什么**：今日是「样板日」—— 冲高 ≥7%（且 <18%）、量比 ≥1.3、**收盘离开最高**（≥2.8%，
  或上影 ≥15% 范围）、收盘不是光头阳线、且不属于「吵起来 / 像出货」。记下今高，今天不买。
- **2026-10-09 加的一道过滤**：**收盘离开最高 ≤2.9%**（去掉长上影、弱收盘那一档）。
  实测把「次日过今高」从 39.0% 提到 51.2%、5 日到线率 46.3%→54.3%、破位率 38.9%→29.8%，
  名单保留 **47.6%**（生产不去重口径）。
  ⚠️ 与原来那条「收盘离开最高 ≥2.8%」合起来读会像个矛盾区间 —— 其实**留下的样本 94.5%
  走的是「上影 ≥15% 范围」那条路**：所以这一格现在的实际形态是
  **「冲高、收盘贴在最高 2.9% 以内、且带明显上影」**，与原型「冲高回落、收盘离开最高」
  的取向**是反的**（这是有意换的，数字上站得住）。
- **证据**（同板块基准）**+0.69 / +1.13 / +1.79 / +2.44**（n=2130）；
  （全市场基准）+1.07 / +1.58 / +2.01 / +3.28
- **线上成绩单**（16 个扫描日）：到线率 **55.9%**、破位率 35.3%
- **怎么用**：**观察清单，不是买点**。明天盘中真正过了今高才动手；收盘才看见的默认不追。
- **局限**：过线率与破位率仍是 56% / 35%，离「筛出了会不会过线」还有距离；
  收益的改善是温和的（5 日 −0.28%→−0.10%，同一窗口）。

### 2.2 明天预案 `wudao_start` —— 动手档（按预案）

- **是什么**：昨天是样板 + **今天放量（≥1.5）过昨高** + 今收 ≥ 昨高×0.98 + 收红。
- **名字**：2026-10-09 从「今天可买」改名 —— 判定**收盘后**才跑，那条买点（刚过昨高）盘中早过了，
  叫「今天可买」名不副实。**判定一字未动，只改名字**。
- **证据**（同板块基准）**+0.34 / +0.80 / +0.66 / −0.75**（n=599）；
  （全市场基准）+0.78 / +1.31 / +0.79 / −0.21
- **线上成绩单**：到线率 83.1%（那条线当天已过，实为**站住率**）、破位率 40.0%
- **怎么用**：这是一份**明天按预案跟**的名单；动手仍要等明天真正站上昨高。
- **局限**：60 日转负；样本比「明天盯」小一个量级（599 vs 2130）。

### 2.3 洗完可盯 `wudao_wash2` —— 观察

- **是什么**：样板 → 启动 → 洗盘，且洗盘日够温和（涨跌幅绝对值 ≤3%、实体 ≤3.5%、
  收盘 ≤ 启动收盘×1.04）。
- **证据**（同板块基准）+0.41 / −0.05 / +0.30 / **−1.82**（n=638）；
  （全市场基准）+0.74 / +0.36 / +0.62 / −1.18
- **线上成绩单**：到线率 41.3%、破位率 44.0%
- **怎么用**：观察。洗盘日的纪律是「只观察记账，不追尖、不加仓」。
- **局限**：样本小、10 日起就贴地；长档明显负。

### 2.4 华宝早期 `huabao_early` —— 只观察

- **是什么**：连阳 ≥3 + 贴 MA5 + 量由缩转放 + MACD 抬头。**没有搬**它的资金流与分时两步
  （我们用 iFinD DDE、口径不同；对方「取不到资金流」本来就不淘汰）。
- **证据**（同板块基准）**−0.16 / +0.21 / +0.42 / +0.30**（n=3633）；
  （全市场基准）+0.43 / +0.84 / +0.83 / +1.46
- **⚠️ 最重要的一条**：它的「正超额」**基本全是板块 beta** —— 5 日从 +0.43 掉到 −0.16。
  别拿它在全市场基准下的数字说事。
- **怎么用**：**更早一档、只观察**，真正动手要等走出「明天盯 → 明天预案」。

### 2.5 洗后可盯 `pile_wash_ready` —— 动手档（小仓）

- **是什么**：堆量吸筹 → 放量拉升 → 缩量洗盘，且现价**贴近或越过洗盘高**。
- **证据**（同板块基准）**+0.07 / +0.07 / −0.20 / +0.67**（n=1010）；
  （全市场基准）+0.36 / +0.43 / +0.13 / +2.21
- **⚠️ 同样基本是板块 beta**（5 日 +0.36 → +0.07）。
- **线上成绩单**：到线率 82.2%、破位率 3.4%（用真作废位，不是代理）
- **怎么用**：这一格才是「可小仓试」的那一档（明天盘中放量过洗盘高再进，破作废位走）。
- **局限**：**站上「洗盘高」这条线太近** —— 站上去不代表有肉（到线率 82% 但收益贴地）。

### 2.6 缩量洗盘中 `pile_wash_wash` —— 主观察

- **是什么**：同上的多日结构，但**还没贴近洗盘高**（拉升后横着、量掉回拉升期）。
- **2026-10-09 加的位置门槛**：**现价 ≥ MA60 × 1.08**。不加它这个标签**等于全市场平均**
  （基线 +0.45/+0.37/+0.19/+0.92，n=6707 —— 那是描述，不是筛选）。
  按位置一拆就分开了：门槛之上（n=3284）**+1.08/+1.31/+1.31/+2.43**、
  门槛之下（n=3423）−0.16/−0.53/−0.88/−0.52；按日期对半拆两半都为正。
- **证据（加门槛后）**（同板块基准）**+0.65 / +0.91 / +0.71 / +2.47**（n=1940）；
  （全市场基准）+0.84 / +1.05 / +0.96 / +3.87
- **怎么用**：**主观察** —— 记下洗盘高、缩量别乱砍。不是买点档。
- **局限**：门槛在近一年的回测里留下 **49%**（3284 / 6707），线上近期的一天实测 726 → 166
  —— 仍是个大列表，别指望它变成小池子。

## 3. 一页结论

| 池子 | 定位 | 板块内超额（5/10/20/60 日） | 一句话 |
| --- | --- | --- | --- |
| 明天盯 | 观察 | **+0.69 / +1.13 / +1.79 / +2.44** | 板块内真有超额，但只是「值得看一眼」 |
| 明天预案 | **动手（按预案）** | +0.34 / +0.80 / +0.66 / −0.75 | 收盘后才知道，明天过昨高才动手 |
| 洗完可盯 | 观察 | +0.41 / −0.05 / +0.30 / −1.82 | 样本小、长档负 |
| 华宝早期 | 只观察 | −0.16 / +0.21 / +0.42 / +0.30 | **之前看着好全是板块 beta** |
| 洗后可盯 | **动手（小仓）** | +0.07 / +0.07 / −0.20 / +0.67 | 到线率 82% 但收益贴地，线太近 |
| 缩量洗盘中 | 主观察 | **+0.65 / +0.91 / +0.71 / +2.47** | 加了位置门槛才从「描述」变成「筛选」 |

**两句话总结**：
1. **板块收窄（创业板+科创板）是站得住的** —— 换成同板块基准后，「明天盯」「缩量洗盘中」
   仍有正超额；而全市场口径下的命中以同板块为基准多为负（明天盯 −0.06、明天预案 −0.45、
   华宝早期 −0.51），说明**主板那批命中确实拖后腿**。
2. **六个池子里只有两个在板块内真有超额**：「明天盯」和「缩量洗盘中」。
   其余四个（尤其华宝早期、洗后可盯）在全市场基准下的好看数字**主要是板块 beta**。

## 4. 已知局限与坑

- **一段行情**：260 根 ≈ 近一年，只跑了一个窗口；`history.db` 有 5 年但只有 140 只，
  横截面太窄做不了这种判断。
- **两种基准别混用**：同一个池子、同一段数据，「全市场基准」普遍比「同板块基准」高 0.2~0.6pp
  （5 日档）。写结论时必须写清用的是哪个。
- **回测 ≠ 页面**：回测同票 20 日去重，生产落库不去重 —— 页面一天可能几十只，回测命中数会少。
- **个股分析页的「复盘关联」是窗口内的「天数」，不是历史累计**（2026-10-09）：
  「涨停 N 天 / 龙虎榜 M 天」数的是 **`limit_pool` / `lhb` 两张表各自覆盖的那些交易日**
  （≈ 近一年、随采集滚动），**不是这只票上市以来的累计**。两张表窗口不一定一样，所以页面上
  分开标（`窗口 X / Y 个交易日`），`title` 里也写着「不是历史累计」。
  ⚠️ 看到「涨停 12 天」别读成「这辈子涨停 12 天」。
  ⚠️ 两个都按**去重交易日**数：`limit_pool` 主键含 `pool_type`、`lhb` 主键含 `reason` ——
  `lhb` 里同一天多个上榜原因是多行（实测 21236 行里有 2557 个「票-日」是多行、最多 6 行），
  早先按行数数会把「一天 6 个原因」显示成「龙虎榜 6 次」。
- **悟道页那列「板块」近一半是「—」，那是口径不是漏采**：这一列只记
  「这只票**最近一次涨停是因为哪个题材**」（开盘红涨停天梯），而开盘红**没有**
  非涨停个股的题材归属接口 —— 从没涨停过的票天然是空。实测空率（2026-10-09）：
  明天盯 / 明天预案 **0%**、缩量洗盘中 ~45%、**华宝早期 ~47%** ——
  **票越强越全，安静型池子最空**。
  想要「公司做什么生意」看右边那列 **`行业`**（同花顺三级路径、覆盖全 A 100%），
  **两列不是一个口径、谁也不顶谁**。
- **线上成绩单只覆盖 2026-09-10 起**（`Settings.pool_track_start`）—— 那天的候选范围才定稿，
  更早的命中是另一套口径。要看新口径的数字，**得用当前判定重扫**
  （`POST /api/admin/patterns/scan?date=`，幂等零配额）。
- **重扫/改判定的时间点**：15:05 那轮的**尾部链路**整条包在 `collect_guard` 里、会占到 15:13 之后，
  别在这时重扫（会连吃 409）；更要紧的是 **15:00 前后绝不能占着锁**（`_run_daily` 拿不到锁是
  跳过且不重试）。
- **安静型标签**（华宝早期、缩量洗盘中）**必须配位置类门槛**才有筛选力 —— 纯结构描述 = 全市场平均。

## 5. 怎么复现

```bash
# 单个池子（板块按生产口径）
python scripts/backtest_patterns.py --pattern wudao_sample --board wudao
python scripts/backtest_patterns.py --pattern pile_wash_wash --board wudao

# 换 5 年长历史（只有 140 只，仅作参考）
python scripts/backtest_patterns.py --pattern wudao_sample --board wudao --history
```

判定阈值与它们的实测注释都在 `backend/app/services/patterns.py` 的常量块里，
每个常量旁边写着「这个数是从哪来的」。

## 6. 附：admin 页的「最近访问」（2026-10-09 改）

与选池无关，但**很容易误读**，而且判断「这份清单/成绩单还新不新」时会顺手去看它，所以记一笔。

- 那一列是 **「最近访问」**（字段 `AppUser.last_seen_at`），**不是「最近登录」**：
  任何带会话的请求都会刷新它，按 **1 小时**节流。
- **为什么必须这么改**：会话是**滑动续期 30 天**的 —— 会员只要一直在用就**永远不用重新登录**，
  原先只记「登录那一刻」的话，这一列会一直停在注册那天（所以 09-28 注册的三位曾一直显示 09-28）。
- ⚠️ **它不代表数据新鲜度**。池子与成绩单是这台机器上的定时任务算的，跟有没有人登录无关；
  判断「新不新」要看 **admin 页的「采集日志」** 与 **成绩单里的扫描日**（见 §4）。
- 实现细节与「物理列名为什么仍叫 `last_login_at`」记在设计文档 §8.90，这里不重复。
