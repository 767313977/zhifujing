## 1. 缓存诊断接口安全（P0.4-01）

### 1.1 修改

`/api/research/meta` 现在依赖 `current_user`：

| 调用者 | 返回内容 |
| --- | --- |
| 普通登录用户 | 只返回三条策略的 `id/version/status`；**不含** `cache` |
| 管理员 | 额外返回 `cache.state / reason / identity(db_uuid) / revisions` |
| 未登录 | 401（沿用全站 `require_login`） |

- 无论是否管理员，缓存不可用都会写**服务端日志**（同一原因 60 秒节流）；
- 非管理员拿不到数据库路径、设备号、inode、db_uuid、异常文本；
- 内部身份校验逻辑未削弱：缓存键仍使用 `(路径, dev, inode, db_uuid)` + 修订版本。

### 1.2 验证

- 单元测试：`test_meta_hides_cache_details_from_normal_user`、`test_meta_shows_cache_details_to_admin`；
- 实际服务验证：普通测试账号请求 `/api/research/meta`，返回键仅为 `trend, low_start, sector_state`。

## 2. 生产规模性能门禁（P0.4-02）

### 2.1 环境

- 数据：`b1_research.db` 的在线一致性副本（1.18 GB，目标窗口 171 万条成分记录，5,261 只股票）；
- 副本安装修订水位后 `cache.state=ready`（db_uuid `400ea0fc...`）；
- 本地 Windows、单进程、SQLite WAL；所有写操作只发生在副本，测试后副本已删除；
- RSS 用 `GetProcessMemoryInfo(PeakWorkingSetSize)` 取得；CPU 用 `time.process_time()`。

### 2.2 场景结果

| 场景 | 结果 |
| --- | --- |
| 未安装修订水位（缓存关闭） | trend 1.05~1.18 s；low 6.10~6.18 s；sector 0.22~0.23 s（每次真实查库） |
| 已安装（缓存启用）冷查询 | trend 1.00~1.09 s；low 5.77~6.31 s；sector 0.15~0.29 s |
| 热缓存 P50/P95/P99 | trend 2.44/2.92/3.07 ms；low 1.66/2.22/2.49 ms；sector 2.12/2.90/3.02 ms |
| 服务重启后首次访问 | **7.54 s（冷查询，computes=1, hits=0）**；此前报告的「0.005 s」是**同进程内重建 engine 后命中进程内 LRU**，不是进程重启，已修正 |
| 同键并发 8 请求 | 实际计算 **1** 次，墙钟 6.36 s，无错误，返回行数一致 |
| 不同交易日并发 4 请求（未限流） | 墙钟 44.65 s，P50 42.67 s，峰值 RSS **2,973 MB**，无错误 |
| 不同参数并发 4 请求（未限流） | 墙钟 46.87 s，P50 45.01 s，无错误 |
| **加并发限制后**（同 4 个不同交易日） | 墙钟 **29.83 s**，单请求 13.3/15.0/28.1/29.8 s，峰值 RSS **1,602 MB**，无错误 |
| 失效后并发冷查询 4 请求 | 单次计算，墙钟 6.04 s（single-flight 生效） |
| 多进程（2 个独立进程） | 6.03 / 6.07 s，结果哈希完全相同 `b8706484...` |
| 读写竞争（写 2 万行 + 2 读线程） | 写 0.12 s、0 错误；读 p50 3.34 s、0 错误（读缓存被每次提交失效） |
| 数据库文件被移除后请求 | 抛 `OperationalError`，**未返回旧缓存** |
| 触发器写入开销（5 万行，隔离副本） | 无触发器 1.45 s → 有触发器 3.99 s；重复 UPSERT 0.17 s；UPDATE 0.09 s；DELETE 1.34 s；回滚 +0；WAL 37.7 → 42.9 MB |
| CPU | 冷/热批次合计约 59 s / 215 s（单进程，含 20 轮热缓存压测） |

### 2.3 已实施的限流（本轮新增，未提交）

- 全市场 `low-start` 冷扫描并发上限 **2**，等待上限 **20 s**；超时返回 **503**「研究计算繁忙，请稍后重试」；
- 同键请求继续由 single-flight 合并；
- 不缩小股票池、不缩短 250 日窗口、不改复权口径；
- 前端已有「加载中…」状态，6 秒冷查询期间有明确反馈；
- 测试：`test_low_start_rejects_when_concurrency_slots_exhausted`、`test_low_start_busy_maps_to_503`。

### 2.4 限制

- 限流是**进程内**的：部署若跑多 worker，每个 worker 各自 2 个槽位，总并发会翻倍。该项目调度器要求单进程运行，生产方案应明确单进程；
- 单次冷扫描峰值内存约 700~800 MB，2 并发约 1.6 GB；这是本轮未优化的已知成本；
- 冷查询仍约 6 秒，未达 2 秒；如需进一步压缩需盘后预计算（另行审批）。

## 6. 阻断项与结论

**仍有上线阻断：**

1. **内存风险尚未解决**：单次全市场扫描约 700~800 MB，2 并发约 1.6 GB；尚未证明在生产可用内存内安全；
2. B2.1 历史回补未完成（当前 37/60 天），最终数据验收无法出具；
3. 修订水位迁移尚未在任何生产等价环境演练并获批；
4. 缓存只在单进程内生效，多 worker 部署需明确单进程约束；
5. 冷查询 6~7.5 秒，虽已限流，仍需容量评估。

**可以准备生产发布的先决条件：**

1. B2.1 60 日完成并通过最终对账；
2. 在隔离副本完成迁移演练与回滚演练，取得批准；
3. 明确单进程部署与内存预算；
4. 产品确认错误态是否需要独立重试按钮。

在此之前，不建议对外发布 `/research`。
