## 3. 新增 API（全部 GET、只读、沿用登录鉴权）

| 接口 | 参数 | 说明 |
| --- | --- | --- |
| `/api/research/meta` | — | 策略 id / 版本 / 验证状态文案 |
| `/api/research/trend` | `date`、`min_rps60`、`min_trend_days`、`limit≤200`、`exclude_st`、`exclude_bse` | 趋势研究候选 |
| `/api/research/low-start` | `date`、`limit≤200`、`max_position`、`min_platform_days`、`max_platform_height`、`max_vol_contraction`、`exclude_st`、`exclude_bse` | 低位启动研究候选 |
| `/api/research/sector-state` | `date`、`taxonomy`（`kph_selected`/`kph_industry`）、`limit≤200` | 板块状态 |

约定：

- 库内无日线时返回 404（`{detail}`），前端按空态处理；
- 所有查询基于目标交易日**及以前**的数据，不做未来函数；
- 响应均带 `trade_date`（实际数据日）与 `coverage`（覆盖数量/状态）；
- 板块接口额外返回 `requested_date`：请求日无数据时回退到最近可用日，两者分离；
- 单次不触发任何外部采集；无写操作。

## 4. 指标与公式

### 4.1 趋势研究

候选来源：`rps_daily(trade_date=D).rps60 >= min_rps60`，按 RPS60 降序，取 `limit*8` 上限再计算。

| 指标 | 公式 |
| --- | --- |
| `retN` | `∏(1 + pct_chg/100) − 1`，最近 N 根，可用数 < 90% 时返回 `null` |
| `maN` | 最近 N 根收盘均价 |
| `maN_slope` | `MA_N(D) / MA_N(D−5) − 1`（%） |
| `trend_days` | 从当日向前数，收盘 > 当日 MA20 的连续天数 |
| `off_high60` | `收盘 / max(high, 最近60根) − 1`（%） |
| `amount_ratio20` | `当日成交额 / 前 20 日成交额均值` |
| `state` | 未满足条件 ≤2 条 → `技术特征符合`；收盘 < MA60 且 MA60 斜率 <0 → `当前条件失效`；其余 `条件未满足`；K 线 <130 根或 RPS60 缺失 → `数据不足` |

每条命中/未满足条件都返回带实际值的文本（如 `收盘 12.31 > MA20 11.80 > MA60 11.20`），不使用综合评分。

### 4.2 低位启动

候选池：`stock_universe`（约 5,261 只），排除 ST / 北交所，K 线 <200 根跳过。

| 指标 | 公式 |
| --- | --- |
| `pos_pct` | `(收盘 − 250日最低) / (250日最高 − 250日最低) × 100` |
| `platform_days` | `min(40, 可用根数 − 21)` |
| `platform_height` | 平台区间（不含当日）`最高/最低 − 1` |
| `vol_contraction` | `std(pct_chg, 前20日) / std(pct_chg, 前60日)`；**不含当日**，避免突破长阳抬高分母 |
| `breakout` | `收盘 > 平台高点 × 1.001` |
| `state` | 突破 + 量比≥1.3 + MA20 斜率>0 → `突破确认`；仅突破，或 MA20 斜率>0 / 量比≥1.2 → `启动候选`；其余 `低位观察` |

阈值全部由接口参数暴露，默认值只是研究起点。

### 4.3 板块状态

取最近 61 个有数据的交易日：

| 指标 | 公式 |
| --- | --- |
| `ret5/10/20/60` | 板块 `pct_chg` 复利 |
| `rps20` | 每日用 20 日收益在当日板块间做中位秩分位 `(i+0.5)/n×100`，取目标日值 |
| `strong_days` | 从目标日向前，`rps20 ≥ 80` 的连续天数 |
| `amount_ratio20` | `当日成交额 / 前 20 日均值` |
| `up_ratio` | 当日 `sector_member.pct_chg > 0` 的占比 |
| `core` | 当日成员中涨幅前 5 |

状态：`rps20≥90` 且 5 日前 <80 → 新晋强势；`rps20≥80` 且 `strong_days≥3` → 持续走强；`rps20≥60` 且 `|ret5|≤3%` 且量比<1 → 强势整理；`rps20≥60` 其余 → 强度回落；`rps20≤20` → 持续弱势；中间 → 中性；**当日无成分股数据 → 数据不足**（不填 0）。

## 5. 数据覆盖与状态规则

- 覆盖不足时返回 `state=数据不足` + `missing[]`，指标字段为 `null`，前端显示 `—`；
- 板块广度只统计**当日已有 `sector_member`** 的板块，未回补板块明确标「数据不足」；
- 返回体 `coverage.note` 固定说明：「sector_member 仅覆盖已回补板块；未覆盖板块的广度显示数据不足」；
- 不使用任何模拟数据、不使用未来日期；
- 趋势模板固定文案：`研究假设：统计稳定性不足，未通过正式策略有效性验证`；低位启动：`研究特征组合：仅用于观察，未验证预测能力`；板块状态：`市场表现特征，不代表未来涨跌`。

## 6. 页面结构与交互（`/research`）

三 Tab（沿用 `Segmented`）：

1. **趋势研究**：日期选择、加载/错误/空态；列 = 代码/名称、行业、收盘、RPS20/60/120、MA20/60/120、趋势天数、量比、距高点、状态、依据/未满足/缺失、`+自选`；
2. **低位启动**：列 = 代码/名称、行业、收盘、区间位置、平台天数/振幅、波动收敛、量比、RPS20、状态、依据、`+自选`；
3. **板块状态**：列 = 板块、RPS20、5/10/20/60 日收益、成交额比、上涨占比、强势天数、状态、核心股（`StockLink` 可跳个股）。

顶部常驻：策略状态 + 版本 + 覆盖说明；`低位 = 区间位置，不等于股价便宜` 与「板块状态不代表未来涨跌」均以文案显式展示。

补充交互（验收整改）：

- 搜索框按 代码 / 名称 / 行业 过滤，无匹配时显示「没有匹配…的条目」；
- 表头可点击排序（趋势：收盘/RPS60/趋势天数/量比/距高点；低位：收盘/区间位置/波动收敛/量比/RPS20；板块：RPS20/20 日收益/成交额比/上涨占比/强势天数），缺失值恒沉底，不提供综合分排序；
- 切换 Tab 时清空搜索与排序，日期切换保留当前 Tab。

### 9.3 性能（本地 `b1_research.db` 只读，2026-10-09，与 B2.1 回补并发执行，数值偏保守）

| 接口 | 候选池 | 冷缓存 | 热缓存 |
| --- | --- | --- | --- |
| `/research/trend` | RPS60≥60，800 只进计算 | 1.27 s | 0.001 s |
| `/research/low-start` | 5,261 只全市场 | 6.08 s | 0.001 s |
| `/research/sector-state` | 273 个板块 × 61 日 | 0.22 s | 0.001 s |

结论与限制：

- 已加入**服务端结果缓存**（键＝库路径 + 交易日 + 参数 + 数据版本，TTL 10 分钟，LRU 16 条）；热缓存 <2 ms，达到 P0.3 的 2 秒目标；
- 优化前后逐样本对账：三个接口 120 行结果与基线 JSON **完全一致**；
- 低位启动冷查询仍约 6 秒，瓶颈是 SQLite 读取 1.32M 行（原始 SQL 取数即 5.43 秒），不是指标计算；详见 P0.3 报告；
- 缓存只作用于文件库，内存库（测试）不走缓存，避免跨用例串味；
- 未降低扫描范围、未缩短指标窗口。
