## 2. 生产服务器资源（P0.6-02）

- 仓库不包含服务器登录凭据（README 明确脱敏），本轮**无法执行** `free -m` / `systemctl show` 等远端只读检查；
- 因此「服务器总内存、Swap、cgroup 限制、采集峰值、其他进程占用」**均未确认**；
- 这是发布候选的**硬阻断项**，不能凭本地数据推断生产容量。

### 2.2 仓库内可确认的部署事实

| 项 | 事实 | 来源 |
| --- | --- | --- |
| Worker 数 | 1（`python -m uvicorn app.main:app`，无 `--workers`） | `deploy/install.sh` |
| 内存限制 | 未配置 `MemoryMax` | systemd 单元 |
| 反向代理 | `proxy_read_timeout 600s` | `deploy/setup_nginx.sh` |
| 绑定 | `127.0.0.1:8000`，SQLite 同机 | `deploy/install.sh` |

### 2.3 上线前必须由运维执行（只读）

```bash
free -m
nproc
systemctl show fupan -p MemoryCurrent -p MemoryMax -p TasksCurrent
systemctl cat fupan
systemctl status fupan --no-pager | head -20
journalctl -u fupan --since "7 days ago" | grep -iE "killed|oom|memory" | tail
```

同时确认实际进程数（`ps -o pid,cmd -C python` 或 `systemctl status` 的 Main PID），**若发现多 worker，现有单 worker 性能结论作废**，必须重新评估全局并发。

### 2.4 并发决策

- 默认 **1**；只有服务器内存与采集峰值实测通过、且单 worker 确认后，才允许 2；
- 不按“总内存达到某值”自动提高；
- 保留 503、`Retry-After: 5`、同键 single-flight、失败释放。

副本：`p06_migrate.db`（1,282.8 MB）；备份用 SQLite 在线 API，`quick_check=ok`；迁移前无同名对象。

| 步骤 | 结果 |

1. 应用回退到不依赖 `data_revision` 的版本（缓存自动 fail-closed，结果正确但变慢）；

3. `quick_check` 与关键表行数核对；
4. 恢复旧应用版本，确认接口正常；
5. 不能只删表不删触发器（会导致所有写入失败）。
