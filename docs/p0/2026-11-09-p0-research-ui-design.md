# P0 盘后研究界面设计（第一轮，不编码）

> 日期：2026-11-09
> 依据：B1/B2 研究结论；P0 只做「研究展示、筛选、解释、历史验证」
> 原则：**研究指标 ≠ 已验证策略**；不生成确定性买入建议；不部署生产

---

## 2. P0-1 板块轮动研究界面

### 2.1 数据与接口

| 指标 | 来源 | 现有接口 | 计划 |
| --- | --- | --- | --- |
| 5/10/20/60 日 RPS | `sector_daily` | `/pools/sector-rps`（仅 5/20） | 扩展到 10/60，新增 `rotation-state` |
| 历史排名/排名变化 | `sector_daily` | `/sector/rotation`（只给每日前 N） | 新增逐板块 `rank-series` |
| 成交额/20 日均值 | `sector_daily.amount` | `/sector/series` | 服务层计算 `amount_ratio_20` |
| 内部上涨占比 | `sector_member` | `/sector/members` | 用当日成员计算；缺日标 `数据不足` |
| 强势持续天数 | `sector_daily` | 无 | 服务层计算 |
| 状态分类 | 规则 | 无 | 新晋/持续走强/强势整理/强度回落/持续弱势/数据不足 |
| 历史回放 | 按 `date` | `Sectors` 已有日期参数 | 严格 as-of；事后结果单独分区 |

### 2.2 状态规则（确定性，可复现）

与 B2 设计一致：`rps20 ≥ 90` 且 5 日前最高 <80 → 新晋强势；`rps20 ≥80` 且 `strong_days ≥3` → 持续走强；`rps20 ≥60` 且 `|ret5| ≤3%` 且 `amount_ratio_20 <1` → 强势整理；`rps20 ≥60` 但较 5 日高点降 ≥15 分位或排名降 ≥10 且 `ret5<0` → 强度回落；`rps20 ≤20` 且 `ret20<0` 连续 ≥3 天 → 持续弱势；指标缺失 → 数据不足。

### 2.3 UI

- 表格列：板块、状态、RPS5/10/20/60、排名及 5 日变化、成交额比、广度（含日期）、持续天数、核心股、数据覆盖；
- 状态标签 hover 显示 `reasons / missing`；
- 点击板块 → 现有右侧详情；点击股票 → `StockLink`，URL 保留 `date/taxonomy/state`；
- 顶部固定提示：「状态是市场表现特征，不代表未来上涨」。

## 3. P0-2 趋势股研究界面

### 3.1 指标

- MA20/60/120 及斜率；
- 收盘相对均线位置；
- `ret20/60/120`；
- `rps20/60/120`；
- 趋势持续天数；
- 成交额/20 日均值、突破/回调量比；
- 相对市场、相对行业（行业归属当前分类，标注局限）。

### 3.2 结果行

| 字段 | 说明 |
| --- | --- |
| 代码/名称/行业 | 基础 |
| 命中条件 `reasons[]` | 带实际值，如 `rps60=78.5`、`trend_days=11` |
| 未满足条件 `unmet[]` | 如 `MA120 仍向下`、`距 60 日高点 -18%` |
| 数据覆盖 `missing[]` | 如 `RPS250 不足`、`行业归属缺失` |
| 风险标记 | ST（当日名称）、北交所、低流动性、短历史、趋势恶化 |
| 验证状态 | 固定文案：**「趋势模板目前为研究假设，统计稳定性不足，未通过正式策略有效性验证」** |

### 3.3 交互

- 筛选条：RPS20/60、趋势天数、均线排列、成交额比、距高点、市值、排除 ST/北交所；
- 排序：显式字段，不提供黑盒综合分；
- 行展开：解释 + 历史验证摘要（样本数、区间、基准、MAE、分块结果）；
- 操作：加自选、加交易计划（带策略版本/筛选条件）、复制代码；不做自动下单。

---

## 4. P0-3 低位启动研究界面

- 指标：历史区间位置（250 日）、平台天数/振幅、波动收敛（ATR20/ATR60）、突破基准（只用 T 前平台高）、量比、MA20 斜率、RPS 改善、板块状态；
- 状态：低位观察 / 启动候选 / 突破确认 / 回踩观察 / 信号失效 / 数据不足；
- 页面必须显示：「低位 = 历史区间位置，不等于股价便宜；启动 = 技术特征组合，不代表后续上涨」；
- 阈值全部配置化；默认值只是研究起点；
- 未经时间样本外验证，不提供综合买入评分。

## 5. P0-4 研究结果与交易计划联动

交易计划新增/保留字段：

| 字段 | 说明 |
| --- | --- |
| `signal_date` | 信号日（T） |
| `strategy_id` / `strategy_version` | 趋势/低位/共振 + 版本 |
| `params` | 当时的筛选参数（JSON） |
| `metrics` | 当时可用的指标快照（RPS、MA、量比等） |
| `reasons[]` / `unmet[]` | 入选理由与未满足条件 |
| `invalidations[]` | 失效条件 |
| `data_coverage` | 覆盖日期与缺失项 |
| `validation_status` | `研究假设 / 证据不足 / 负结果 / 有条件成立` |

历史候选重新计算时，**不得覆盖**当时保存的 `metrics/reasons/params`。

## 6. 跨页状态

沿用现有 URL 参数约定：

- `Sectors`：`view/taxonomy/date/code/rot/rotdays/ladder/curve/flow/flowdays`；
- `Patterns`：`date/patterns/days/boards/phase/...`；
- 新增：`Pools` 的 `tab/date/rps20/rps60/trend_days/state/order`；
- 跳转个股：带 `from/date/params`，返回时恢复。

---

## 7. 性能与安全

- 所有新接口只读本地库；
- 单次查询上限：`limit ≤200`、窗口 ≤60 日、状态计算缓存；
- 不在页面请求里触发外部采集；
- 历史回补只走脚本，页面不可触发；
- 保持现有登录鉴权；
- 新接口默认只读、无写操作；
- 大计算（回测）走离线脚本或受限接口，不阻塞业务。

## 8. 实施顺序（P0 受控开发）

1. P0-1 板块状态 + 排名序列（依赖 B2.1 数据覆盖标记）；
2. P0-2 趋势研究池（依赖 B2.2 行业中性化结论）；
3. P0-3 低位启动池（依赖 `build_bars`，新增特征层）；
4. P0-4 计划联动字段；
5. 首页四区整合（折叠/标签，不重复堆指标）。

每步先测试、再评审；不部署生产。

---

## 9. 明确不做

- 「高胜率」「确定性机会」「强烈推荐」等标签；
- 未经样本外验证的综合买入评分；
- 自动下单/券商接口；
- 实时盯盘、逐笔；
- 页面触发历史全量回补；
- 替换正式 track 路由。
