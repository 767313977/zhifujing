# B0.1 历史数据完整性审计报告

> 日期：2026-11-08
> 分支：`feat/b0-research-foundation`

## 1. 审计口径

| 项 | 规则 |
| --- | --- |
| 交易日 | 优先 `trade_calendar`；无日历时退化为日线日期并集 |
| 完整日 | 当天行数 ≥ 窗口内单日最大行数 × 50%（与 `pattern_track` 同一思路） |
| 历史 ST | 用 `stock_daily.name` 的**当日值**，不用最新名字 |
| 退市 | 用「最后一根日线显著早于全库最后日期」近似，只是缺口提示，不能证明退市 |
| 覆盖率等级 | A：≥95% 且 ≥250 日；B：≥70%；C：>0；D：无数据 |

### 2.2 `stock_daily` 明细

```json
{
  "codes": 5303,
  "median_rows_per_day": 5025.5,
  "max_rows_per_day": 5283,
  "incomplete_days": 0,
  "codes_ge_250_rows": 5033,
  "codes_first_seen_after_30d": 353,
  "st_row_count": 67909,
  "st_name_count": 140,
  "name_change_codes": 7,
  "stale_codes_30d": 1
}
```

- **无残缺交易日**：506 天全部达到窗口最大行数的 50% 以上，且 `stock_pool_daily` 没有低于滚动中位数 80% 的日子。
- 353 只代码在数据起点 30 天后才首次出现：次新股与「历史覆盖不全」混在一起，单凭日线无法区分；研究池应按「T 日有行情」而不是当前 `stock_universe` 判定。
- 7 只代码在库内改过简称（含 ST 戴帽/摘帽），说明**逐日 name 是必要的**。
- 1 只代码最后一根日线比全库最后日期早 30 天以上：可能是退市/长期停牌/出池，样本极少。

### 2.3 `sector_daily` / `sector_member`

- `sector_daily` 的 `up_count/down_count` **94,771/94,771 全为 NULL**：板块内部广度不能直接取自本表。
- `net_inflow/member_count` 只有 724 行有值（2026-09-22~23 两天）：资金流历史不足。
- `sector_member` 只有 5 个交易日，且每天只有 1~19 个板块（全市场约 374 个）：**不能据此做任何 20 日以上的历史广度或板块→个股验证**。
- 板块存活：`sector_daily` 有 383 个「板块-口径」键，`sector_basic` 只有 374 个；9 个只在日线出现，20 个最后日期早于全库最后日。不能把当前板块目录当作完整历史目录。

### 3.1 幸存者偏差结论

`history.db` 由腾讯接口按**当前代码池**回补，**没有退市股**（0 只最后日期显著早于 2026 年）。因此：

- 5 年长历史结果必须标注为 **「现存股票样本研究」**，不能称为完整市场策略回测；
- 不能通过删除异常收益股票来「修正」幸存者偏差；
- 需要完整市场结论时，只能使用**较短但有完整覆盖的区间**（主库 506 天），并明确披露缺口。

## 4. 对 B0 的直接影响

| 结论 | 影响 |
| --- | --- |
| 主库日线完整、逐日 name 可用 | 可以做 5/10/20/40/60 日信号研究；ST 按当日 name 修正 |
| 长历史无退市股 | 长历史只能做横向比较，不能宣称无幸存者偏差 |
| `sector_member` 只有 5 天且残缺 | P0-4 板块共振历史验证暂不可做；需 60 日回补 |
| `sector_daily` 广度字段全空 | 板块内部广度只能从 `sector_member` 算，缺日必须标「数据不足」 |
| 板块资金流只有 2 天 | 资金/价格一致性只能做短样本，不能与 255 天价格序列等长比较 |
| RPS 历史混版本 | B0.3 必须用统一版本重算目标区间；新增 20/60 不能改变旧三档语义 |
| `pattern_hit` 只有 26 天 | 形态突破基线只能借助 `scripts/backtest_patterns.py` 的长历史重扫，不能直接用落库命中 |
