## 2. 完整性状态定义

| 状态 | 含义 | 依据 |
| --- | --- | --- |
| `complete` | 完整 | `reported` 已知且 `unique >= reported`，写入数 = 去重数 |
| `partial` | 部分完整 | `reported` 已知且 `0 < unique < reported` |
| `source_empty` | 来源明确无数据 | `reported == 0` 且没有取到行 |
| `unverified` | 无法对账 | 来源没给 `Count`；不能标完整 |
| `failed` | 采集失败 | 请求异常且重试耗尽 |
| `unsupported_history` | 来源不支持该日期 | `errcode=1020` 或当天无 `sector_daily` 板块清单 |
| `not_collected` | 尚未采集 | 仅 dry-run 展示，不落 manifest |

> `partial` / `unverified` 会在下次运行时重试；`complete` / `source_empty` 默认跳过，`--force` 可重取。

## 5. 60 / 120 日回补评估

- 实测速度：0.825~1.26 秒/板块；每天约 374 个板块 → **约 5.1~7.9 分钟/天**。
- 60 个交易日预计 **约 5~8 小时**；120 日约 10~16 小时。
- 本轮**未执行** 60 日回补，只完成 25 个板块的隔离试验；按指令，60 日回补需在试验报告通过后**分批执行**，120 日不执行。
- 若批准 60 日回补，建议：
  1. 在隔离副本上按 5~10 天一批执行，每批结束跑 `--audit-only`；
  2. 每批记录 `run_id`、耗时、`complete/partial/failed` 数量；
  3. 对 `partial` 板块用 `--force` 重取一次；
  4. 全部完成后用来源 `Count` 汇总核对，再决定是否进入 P0-4 历史验证。

## 6. 结论

- 回补链路可用、状态可验证、幂等、可断点续跑；
- 试验的 25 个板块全部 `complete`，来源与落库逐一对账一致；
- 仍然只有 25/374 个板块/天，**不能**据此宣称 `sector_member` 已补齐 60 天；
- B0.5 的「板块强度叠加个股筛选」基线因此只能做 6 条信号的小样本冒烟，不能作为正式结论。
