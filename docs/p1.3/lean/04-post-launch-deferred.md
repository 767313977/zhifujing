## 2. 上线后第 1 周的执行顺序（建议）

1. 第 1 天：观察采集与内存，确认为 G6 通过状态；
2. 第 2 天起：每天跑 1 批 RPS 回填，`--max-days 5`；
3. 第 3 天：看回填耗时，决定是否做 P-03；
4. 第 5 天：跑一次全量测试（P-02）；
5. 第 7 天：补异地备份（P-08），决定是否调缓存（P-04）。

## 3. 明确「不能推迟」的四件事

| 项 | 原因 |
| --- | --- |
| G1 备份可恢复（含恢复演练） | 没有可恢复备份，任何事故都是终局 |
| G2/G3 真实快照迁移演练与行数校验 | 迁移错误的代价是丢历史数据 |
| G4/G5 启动与核心功能 | 上线即不可用等于没上线 |
| G7 回滚演练 | 出事时第一次尝试回滚，成功率最低 |
