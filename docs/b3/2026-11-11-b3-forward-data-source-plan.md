## 3. 推荐的唯一优先数据源

**iFinD**。理由：

1. 已有客户端、限速、错误分类（`IfindRateLimitError`/`IfindQuotaExhausted`）与列名容错；
2. 官方涨跌幅，不需要像腾讯那样从复权序列反推；
3. 成交额单位与 `history.db` 一致（元），不需要换算；
4. 与生产同一家供应商，口径争议最小。

**备选 Tushare Pro**，仅在下列任一成立时切换：iFinD 明确拒绝新增用途、iFinD 无按日全市场
批量接口、或额度不足以支撑每日一次全市场。切换时必须重跑 §4 的字段对账。

## 4. 两个必须先决策的口径问题

### 4.1 北交所覆盖：协议与数据不一致

`history.db`（截至 2026-10-19）按代码段统计：

| 市场 | 代码段 | 现有只数 | 当日有行情 |
| --- | --- | ---: | ---: |
| 沪主板 | 60 | 1,634 | 1,628 |
| 科创板 | 68 | 583 | 583 |
| 深主板 | 00 | 1,469 | 1,333 |
| 创业板 | 30 | 1,390 | 1,388 |
| 北交所 | 43/83/87/88/92 | **32** | **32** |
| 合计 | | 5,108 | 4,964 |

32 只全部是 920 段（如 920025 凯达重工、920493 并行科技），且连续 5 个交易日都是 32，
不是当天缺失。真实北交所上市公司约 270 只 —— 所以**历史样本的「含北交所」实际只含 920 段
的 32 只**，协议文字与数据不符。

两个选项（本轮不擅自改协议）：

- **B1（推荐，先做）**：把协议里的 universe 写成「沪深全部 + 920 段」，与历史数据完全一致，
  换 `STRATEGY_VERSION`。这不是「静默删减」——是把协议改成与数据一致并显式记录。
- **B2（后续单独立项）**：接入全北交所（约 +240 只）。这是**扩大未经历史验证的样本**，
  必须打 `UNVALIDATED_UNIVERSE_EXTENSION`，且历史结论不再直接适用，需要重新验证。

### 4.2 涨跌幅口径

`history.db` 由腾讯不复权日线 + **前复权序列**推出的 `pct_chg`（见 `scripts/backfill_history.py`），
与 iFinD 官方涨跌幅实测差 **0.0000~0.43pp**（`sources/tencent.py` 有记录）。rev20 是 pct 的
复利，amp20/illiq20 用 OHLC 与成交额，因此：

- 若新源用**官方** pct：前瞻因子与原历史因子有极小差异，属口径升级，必须记录版本；
- 若为对齐历史而改用推算 pct：等于主动引入已知误差，不推荐。

建议：**新库用官方 pct**，元数据记录 `pct_source=official`，并在首次接入时用重叠的 20 个
交易日做一次「官方 vs 推算」差异分布统计（只统计，不改历史）。

## 5. 字段映射与单位转换

| 原始字段（iFinD） | 研究字段 | 转换规则 | 校验 |
| --- | --- | --- | --- |
| 证券代码（如 `600000.SH`） | `code` | 取 6 位数字；`.BJ` → 北交所 | 必须匹配 `^\d{6}$` |
| 交易日期 | `trade_date` | 统一为 `Asia/Shanghai` 的市场日期 | 必须在该日 `trade_calendar` 内 |
| 开盘价 | `open` | 元，**不复权** | > 0，非空 |
| 最高价 | `high` | 元，不复权 | ≥ max(open, close) |
| 最低价 | `low` | 元，不复权 | ≤ min(open, close) |
| 收盘价 | `close` | 元，不复权（= 当日实际可成交价） | > 0，非空 |
| 涨跌幅 | `pct_chg` | **百分数**（`2.35` 表示 +2.35%） | −100 < x < 1000 |
| 成交额 | `amount` | 元 | 非空；**缺失时拒绝入库，不得估算** |
| 成交量 | `volume` | 股 | 若源给「手」，用 `amount / 均价` 自洽判定后 ×100（沿用 `tencent._to_shares` 思路） |
| 证券简称 | `name` | 原文 | 非空 |
| （派生） | `board` | 由代码段判定：60/68/00/30/43/83/87/88/92 | 必填 |

硬规则：

- 复权价只用于**收益评价**，绝不作为 `open/high/low/close` 入库；不得把复权价当成交价。
- 不允许用（后来才知道的）复权因子修改历史信号。
- 成交额缺失一律拒绝该日冻结，不用 `volume × close` 估算。
- 任何转换都必须有**合成数据测试**（正常行、缺字段、单位错、代码带后缀、停牌行、北交所行）。

## 6. 独立前瞻库最小表结构

```
backend/data/forward_research.db        # 独立文件，采集程序写、前瞻工具只读
```

```sql
CREATE TABLE stock_daily (
    trade_date   TEXT NOT NULL,
    code         TEXT NOT NULL,
    name         TEXT,
    open         REAL, high REAL, low REAL, close REAL,
    pct_chg      REAL,          -- 百分数
    volume       REAL,          -- 股
    amount       REAL,          -- 元
    board        TEXT,          -- 沪主板/科创板/深主板/创业板/北交所
    source       TEXT NOT NULL, -- ifind / tushare
    ingested_at  TEXT NOT NULL, -- ISO8601 +08:00
    PRIMARY KEY (trade_date, code)
);

CREATE TABLE trade_calendar (trade_date TEXT PRIMARY KEY);

CREATE TABLE data_revision (
    domain     TEXT PRIMARY KEY,   -- 如 "stock_daily:2026-11-12"
    revision   INTEGER NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE ingest_log (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    trade_date TEXT NOT NULL,
    status     TEXT NOT NULL,      -- ok / partial / failed
    rows       INTEGER,
    message    TEXT,
    created_at TEXT NOT NULL
);
```

设计要点：列名与 `history.db` 的 `stock_daily` 完全一致，`research_backtest.load_matrix`
换 `--db` 即可复用；`data_revision` 让 `forward_track_c0._data_revision` 直接取到版本号，
不必退化成文件 mtime。

## 7. 完成时间、交易日历与调用量

### 7.1 时间规则（已在代码中实现，本轮只补测试）

合法冻结窗口 = **D 日 15:30 ~ 下一交易日 09:15**。

- 数据实际完成可以晚于 15:30（例如 22:00 或次日 08:00），只要完整性检查通过；
- 必须拒绝：收盘前快照、盘中行情冒充收盘、数据不完整、窗口已结束的补建；
- 不得为了赶时间提前冻结不完整数据（闸门 5~9 会直接拦下）。

本轮补了两个测试证明窗口边界：`test_forward_accepts_late_data_same_evening`（22:00）、
`test_forward_accepts_late_data_before_next_open`（次日 08:00）。

### 7.2 交易日历

优先 iFinD（若提供）；否则沿用现有 akshare `trade_calendar()` 作为**独立来源**写进
`forward_research.db.trade_calendar`。必须能回答「下一交易日」——闸门 3 依赖它。

### 7.3 调用量估算（基于现有代码事实）

| 方式 | 单日调用 | 40 日预热 | 与月配额 5,452 的关系 |
| --- | ---: | ---: | --- |
| 单票 `stock_history` | ~5,100 | ~5,100（一次性，回补 40 日） | **单日增量就超月配额** → 不可用 |
| 按日全市场批量（待验证） | ~6~10 段 | 40 × 6~10 ≈ 240~400 | 可接受 |

结论：**必须先验证 iFinD 是否有「按交易日返回全市场日线」的批量接口**，并确认它是否包含
成交额与涨跌幅。若没有，则要么改用 Tushare（`daily(trade_date=...)`），要么放弃每日全量。
