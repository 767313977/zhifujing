## 1. 120 分档能做什么、不能做什么

| 能力 | 120 分档 | 说明 |
| --- | --- | --- |
| `daily(trade_date=...)` | ✅ 可用（需先到 120） | 50 次/分、8000 次/天；未复权；停牌无记录 |
| `trade_cal` | ❌ 需 2000 分 | **改用项目现有 AKShare 日历** |
| `stock_basic` | ❌ 需 2000 分 | 证券身份改用**已冻结的 5,108 只清单** |

因此本路线是：**Tushare 只提供日线行情，日历与证券身份由本地既有资料补齐。**

三个随之而来的硬约束：

1. **拿不到 `name`**：`daily` 不返回证券简称。新库的 `name` 从冻结清单
   （`c0_universe_b1_verified.json`，来自 `history.db`）回填，`ST_STATUS_PARTIAL` 风险不变。
2. **拿不到 `list_status` / `delist_date`**：无法自动识别退市与暂停上市。
   前瞻池本就冻结在 5,108 只，不纳入新股，所以“不新增”是设计而非缺陷；
   但“已退市但仍在清单里”只能靠当日无行情间接体现。
3. **拿不到 `stock_basic` 的 BSE 列表**：北交所 32 只的身份核验继续以
   `docs/b3/bse_identity_2026-11-11.json` 为准，`daily` 只负责验证“当日是否有行情”。

## 2. 交易日历方案（不花 Tushare 积分）

来源：项目现有 `akshare_source.trade_calendar()` → `ak.tool_trade_date_hist_sina`。

已确认的代码事实（`backend/app/sources/akshare_source.py:237`）：

- 返回**完整交易日列表**，且**包含未来日期**（注释举例 2026-12-31）；
- 生产每天由 `DailyCollector.collect_calendar()` 写入 `trade_calendar` 表；
- 取“最新交易日”时必须先过滤掉大于今天的部分（现有代码已如此处理）。

前瞻侧用法（待实现，非本轮）：

1. 采集脚本把 AKShare 日历写入 `forward_research.db.trade_calendar`（表已在
   `forward_store.SCHEMA_SQL` 里建好）；
2. `forward_track_c0` 的闸门继续用 `trading_days.is_trade_day/next_trade_day`，
   读同一个库的 `trade_calendar`；
3. **下一交易日 = 日历中第一个 `> D` 的日期**（现有 `next_trade_day` 就是这么取的）。

必须核对的三点（在正式跑之前）：

- 日历已铺到 **D 的下一交易日**（跨年时上游可能还没发布次年日历，届时拒绝冻结）；
- 日历不把周末/节假日当交易日（AKShare 源本身已排除）；
- 导入后 `trade_calendar` 非空，否则 `forward` 会以「没有交易日历」拒绝。

这三点都可在**离线**验证：用 `history.db` 里 1,230 个实际交易日做回归，
检查「D 的下一个实际交易日 == 日历给出的 next」；跨年缺口用手工构造的日历测。

## 3. 北交所 32 只的覆盖验证（只用 `daily`）

因为没有 `stock_basic`，验证只能靠当日返回：

1. 取 2026-10-19 的 `daily`，把 `ts_code` 去后缀；
2. 与 5,108 只清单求交，记录匹配数；
3. 32 只逐只标记「有/无」，并与 `bse_identity_2026-11-11.json` 的代码对齐；
4. 缺口归因：停牌（正常）/ 新上市（不在清单，正常）/ 整段缺失（覆盖不足）/ 行数贴近上限（截断）。

注意：如果 32 只里有多只在当日无返回，无法用 `stock_basic` 判断是停牌还是供应商不覆盖，
**只能记为「待定」，不能直接判为覆盖不足**；判为覆盖不足需要「连续多个交易日整段缺失」。

## 4. 字段映射（与已定方案一致）

`ts_code` → `raw_code`（原文）/ `code`（6 位）；
`trade_date` `20261019` → `2026-10-19`；
OHLC 原值**不复权**；`pct_chg` 原值（`pct_source=tushare_daily`）；
`vol` **×100 → 股**；`amount` **×1000 → 元**，缺失即该行不合格；
`board` 由代码段派生；`name` 来自冻结清单；`source=tushare`；`data_version` 记批次。

同样禁止：用复权因子回填冻结信号；同一序列混用腾讯推算 `pct_chg` 与 Tushare 官方值。
