## 1. 现有接入协议与 THS_HQ 的适用性

### 1.1 项目现在用的是哪一种

| 事实 | 依据 |
| --- | --- |
| 端点 `https://api-mcp.51ifind.com:8643/ds-mcp-servers` | `backend/app/config.py::ifind_base_url` |
| 请求体是 JSON-RPC 2.0（`initialize` / `tools/call`） | `sources/ifind.py::_ensure_session` / `call` |
| 认证头 `Authorization: <IFIND_AUTH_TOKEN>` | `sources/ifind.py::_headers` |

**这是 iFinD 的 MCP 网关，不是官方量化接口（quantapi）。**

### 1.2 THS_HQ 走的是什么

官方手册（`quantapi.51ifind.com/.../manual.html`）原文：

```
requestMethod: POST
requestURL:   https://quantapi.51ifind.com/api/v1/cmd_history_quotation
requestHeaders: {"Content-Type":"application/json","access_token":"","ifindlang":"cn"}
formData: {"codes":"300033.SZ","indicators":"open,high,low,close",
           "startdate":"2024-01-13","enddate":"2025-01-13",
           "functionpara":{"Currency":"MHB","Fill":"Omit"}}
```

FAQ 补充：`access_token` 有效期 7 天，由 `refresh_token` 换取。

**结论：两套凭据体系不同。** 现有 `IFIND_AUTH_TOKEN` 是 MCP 网关令牌，
不能假定可用作 quantapi 的 `access_token`。按任务书「不得将不同接口的 Token 视为通用凭据」，
**这条路线在本轮停止**，不擅自改认证方式、不尝试拿现有 token 去试。

## 3. B1 相对历史 C0 的实际影响（实测）

方法：同一份 `history.db`，同一 `_day_candidates` 与 `_rank_top`；
A = 全池 5,108 只，B = B1 5,076 只。B 的因子值直接复用 A 的原始因子，
只重算池内分位与加权分（与 `factor_score.score_series` 同公式、同 `round(score,1)`）。
开工前先用 `build_candidates(universe=…)` 在 3 个交易日自证两条路径结果一致。

| 指标 | 数值 |
| --- | --- |
| 交易日 | 1,211 |
| 原始 C0 Top20 出现北交所的交易日 | **18 天（1.49%）** |
| 涉及北交所证券 | 6 只（920873×3、920126×10、920079×13、920258×9、920107×8、920059×1） |
| Top20 名单不同的交易日 | **51 天（4.21%）** |
| 席位替换合计 | 78 席（平均每个受影响日 1.53 席，最大单日 5 席） |
| 其中「北交所被换出」 | 44 席（18 天） |
| 其中「纯分位漂移」 | 34 席（33 天，当天原本没有北交所在 Top20） |

**关键结论：不能用 32/5,108 = 0.63% 推断「对 Top20 没影响」。**
- 有 18 天确实是因为北交所被剔除而换人；
- 另外 33 天，虽然 Top20 里没有北交所，但**池内分位分母变了**，
  边界股票的分数在 `round(score, 1)` 处翻转，导致 1~2 席替换。

因此：

1. B1 与历史 C0 **不是严格同一个策略**，必须保持独立版本（当前已用 `c0-2026-11-11-b1`）；
2. 不能把历史 C0 的业绩直接继承为 B1 前瞻的预期；
3. 历史研究结果不改（本轮未重跑、未调参）；
4. 若后续决定把这 32 只重新纳入（§2 已确认身份），B1 的池子回到 5,108，
   上述 51 天差异将消失 —— 届时应换新的 `STRATEGY_VERSION` 与清单哈希，而不是就地改。

## 4. 官方 `pct_chg` 对账规则（修订）

### 4.1 样本

- 两库共同交易日 **≥ 40 个**，确保最近 20 个交易日的 20 日因子窗口完整；
- 预热不足 20 根的日期不参与比较（避免拿缩短窗口当口径差异）。

### 4.2 统一指标

Top20 替换率（逐日）：

```
replacement_rate(d) = (20 - |旧Top20(d) ∩ 新Top20(d)|) / 20
```

统计口径固定为：

| 指标 | 说明 |
| --- | --- |
| 平均替换率 | 全部共同日的算术平均 |
| 最大单日替换率 | 最坏一天 |
| 有替换的交易日占比 | `replacement_rate > 0` 的天数 / 共同日 |
| 因子差 | `rev20` / `illiq20` / `amp20` 逐样本差：均值、P95、最大绝对值 |
| 评分差 | `score` 逐样本差（注意 0.1 分位舍入会放大边界翻转） |
| 受影响股票与日期 | 明细表：日、出、入、三个因子差、分位差 |

原定的「平均名次位移 ≤ 1 位、Top20 替换率 ≤ 10%」保留为**事先声明的相似性指标**。

> 但即使两项都达标，也只能说明「信号口径相近」，**不能**自动升级为
> 「独立历史收益验证通过」。收益结论仍需前瞻样本单独积累。

## 6. iFinD 是否值得进入下一步受控试验

**值得，但当前被凭据与授权卡住。**

支持进入试验的理由（全部来自官方文档）：

1. THS_HQ 明确支持多代码，HTTP 端点清晰；
2. 计费按数据量（单元格），单次 200 万、每周行情 1.5 亿，容量上看一日全市场只需约 2.55 万单元格；
3. A 股日行情 15:07 入库，与现有 15:30 冻结窗口天然兼容；
4. 返回带 `dataVol`，可精确核算成本。

不能现在进入的理由：

1. 现有 token 是 MCP 网关凭据，**不是** quantapi `access_token`；
2. `pct_chg` / `amount` 的指标名官方没有公开字典，必须实测；
3. 单次代码数上限官方未写；
4. 本地留存与研究用途的授权未确认。

**下一步只需要你给两样东西**：可用的 quantapi 凭据（或明确「无」）＋ 对 §5 范围的书面同意。
若凭据不可得，则按任务书建议转 Tushare Pro，不投入开发 iFinD 采集器。
