## 4. RPS 导入最终对账（P1.0-03）

### 4.1 两个数字的口径差异（此前混用的根源）

- **11**：在 10,206 个「导入前已存在主键」中，来源 `ret20` 有值、`ret60` 为空
  的行数（`ret20_only` 类）。它们正是 P0.7 被 `rps60 IS NOT NULL` 过滤掉、
  但目标库已有行的 11 条。
- **5,056**：同样这 10,206 个主键中，来源 `ret20` **非空**的行数（5,045 个
  20/60 都有 + 11 个仅 20 日）。因为四个新列刚加上、原本全为 NULL，这 5,056
  行都发生了实际写入 —— 它是**列级写入行数**，不是「缺失 20 日值」的行数。

### 4.2 逐主键分类（`docs/p1/2026-11-09-rps-pre-existing-keys.csv`，10,206 行）

| 类 | 主键数 | 写入 ret20 | 写入 ret60 | 写入 rps20 | 写入 rps60 | 值不一致 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 20/60 都有值 | 5,045 | 5,045 | 5,045 | 5,045 | 5,045 | 0 |
| 仅 20 日有值 | **11** | 11 | 0 | 11 | 0 | 0 |
| 仅 60 日有值 | 8 | 0 | 8 | 0 | 8 | 0 |
| 四列全空（不进候选） | **5,142** | 0 | 0 | 0 | 0 | 0 |
| **合计** | **10,206** | **5,056** | **5,053** | **5,056** | **5,053** | **0** |

### 4.3 六类数量分别对账

| 类别 | 数量 | 说明 |
| --- | ---: | --- |
| 新增整行 | **1,262,706** | 目标缺失主键（含 10-09 的 155 只新上市） |
| 已存在行补齐 20 日字段 | 5,056 | 行数；对应 `ret20`/`rps20` 各 5,056 次写入 |
| 已存在行补齐 60 日字段 | 5,053 | 行数；对应 `ret60`/`rps60` 各 5,053 次写入 |
| 已有字段一致、无需更新 | 0 | 导入前四列全 NULL，没有「一致但非空」的行 |
| 全 NULL 的窗口不足记录 | 5,142 | 10-09 的 51 行（43 停牌 legacy + 8 停牌覆盖不足）+ 10-21 的 5,091 行 |
| 无底层行情支持的历史记录 | 5,091 | 仅 2026-10-21；保留不可验证状态，不删除、不重算 |

合计校验：`10,206 + 1,262,706 = 1,272,912`；`5,056 + 5,053 − 5,045 = 5,064`
（已存在且进入候选集的主键数）；`10,206 − 5,064 = 5,142`。

### 4.4 其他校验

- 重复执行：`inserted=0`、四列补值 0、总行数不变；

## 6. 软件侧剩余风险

1. 单 worker 结论仅在本机/等价副本验证；多 worker 需重新验收限流与进程内缓存。
2. `low-start` 冷查询 6.8~8.5 s（等价副本 1.4 GB），生产若更慢需确认 nginx 超时。
3. 板块广度依赖 manifest；未导入 manifest 时页面会显示「无 manifest / 广度不可用」，
   这是预期行为，需要写进发布说明。
4. 10-21 的 5,091 行 RPS 保留但被门禁拒绝，若将来补采 10-21 行情需重算后再解除。
