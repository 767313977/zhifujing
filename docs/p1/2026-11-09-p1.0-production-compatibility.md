## 6. 生产库仍需确认的清单（C）

由授权运维只读执行并脱敏回传：

1. `python scripts/schema_inventory.py --db <生产库副本> --compare <发布等价副本> --json ...`
   （在**副本**上跑，不要在生产文件上跑任何工具）；
2. `PRAGMA quick_check`（副本）；
3. 各表 `COUNT(*) / MIN/MAX(trade_date) / COUNT(DISTINCT trade_date)`；
4. 按交易日历外连接的逐日覆盖矩阵；
5. `collect_log` 最近成功时间与失败/重试；
6. 是否存在本机没有的表/列/数据（特别是 `analysis_snapshot`、`user_risk_pref`、
   `trade_plan` 新字段、`sector_member_backfill`）；
7. 备份策略、异地副本、回滚包。

**注意**：`fupan.db` 的修改时间不能作为生产状态证明；本机快照不能替代生产副本。

## 7. 本报告结论

- B 证明了「A 这类旧库 → 目标结构」的迁移、增量导入、启停与回滚**可复现**；
- B 不能证明生产库的结构与数据范围（C 缺失），因此兼容性结论为
  **生产 NO-GO，待 C 证据**；
- 生产执行顺序必须是：一致性备份 → 显式迁移 → 增量导入（按生产主键统计）→
  安装触发器 → 启动验收 → 对账 →（失败时）备份恢复。
